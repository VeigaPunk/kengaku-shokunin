## 2. Suggestions (new; none repeat 10-18 → 11-15)

1. **Factor the C1 replay counters into one frozen, sha-pinned library.** `plans/` holds 18 `*_c1_replay.py` counters (r83–r100), 348,876 bytes in total. Each one is a hand-copied successor of the one before. Q79 forbids editing historical instruments, so every round forks instead. Measured today: `round99_c1_replay.py` shares 261 of its 317 non-blank lines (82%) with `round98_c1_replay.py`. It also redefines the same 8 functions (`sha`, `git`, `blob`, `frozen_table`, `parse_receipt`, `host_tool`, `new_row_defects`, `main`). The real per-round delta is a config block (`PINS`, `FIX_PINS`, `MEMBER`, `MEMBER_CLASSES`, `BASE`) plus at most one new leg. Proposal: write a `plans/replay_lib_v1.py` that holds the shared legs, and pin it by sha256 in each round's `frozen-instruments` table, just as L11 already pins the counter's own bytes. Each round then ships a thin config of about 60 lines. A new leg means a new `replay_lib_vN.py`, which is additive and Q79-compatible because nothing old is edited. The payoff is review depth: a non-author verifier reads a 60-line diff rather than a 17 KB file that is 82% familiar, where a changed leg is easy to miss. This is different from 11-06 idea 1 (forbid tip diffs on frozen paths), which is about immutability. This one is about how the frozen code is structured.
2. **Back-apply the newest legs to old admissions, read-only.** The counters got stronger over time. Round 98 added the `REV <hash>` first line (routed defect 3), and r99 added L11 to close the r98 MutC1 survivor that "no leg bound the counter's own bytes". The r83–r97 counters never had those bindings, so their admissions rest on weaker predicates than today's standard. Proposal: run a one-off, read-only census. For each round in r83–r97, check that the counter's bytes at tip hash to its row in that round's `frozen-instruments` table, and that the round's receipt names the revision it measured. Report a per-round table only, with no re-admission and no ledger edits. Any mismatch becomes a routed finding. This is narrower than 10-23 idea 2 (a gate-yield audit replaying Q-gates on r20–r29 landing commits): that one tested gates for redness, and this one tests old admissions against the two specific bindings added since.

Side observation, not a new idea: root `cases_A.json` is byte-identical to `plans/round92-cases.json`. This is concrete evidence for the root-allowlist idea in 11-14 §2.2, because a stray copy of a frozen case table at the root could be read as authoritative.

## 2. Suggestions (new; none repeat 10-18 → 11-24)

1. **Turn the SOURCES `recheck` column into a due date a script can read.** `corpus/SOURCES.md` has 341 rows (294 mined, 39 rejected, 8 queued) with an `opened` and a `recheck` column. The `recheck` column mixes four formats: an absolute date (46 rows), a relative `180d`/`90d`/`30d` counted from `opened` (197 rows), and `on-release` (98 rows, 74 of them sha-pinned TB2 files). Nothing in the repo computes a due date or names the release signal, so the column records an intention and nothing acts on it. When I compute the dates, nothing is overdue today. But S184 (the TB2 2.1 PR, `30d`) falls due **11-27**, and **59 more rows fall due in one cluster from 2027-01-17 to 01-26**, because the round-24/25 intake opened them all in the same week.
   Proposal: add a `plans/sources_due.py` that normalises every row to `due: YYYY-MM-DD | on-release:<probe>`. For TB2, the probe is "HEAD of terminal-bench-2 ≠ 2fd12b88 or PR #53 merged", which is the check I made above, written as one command. The script prints overdue rows, rows due in the next 14 days, and on-release probes that have fired. Then spread the January cluster across two or three rounds, so one recheck round is not 59 rows. This differs from 11-11 (`as_of`/`revalidate` front matter on knowledge entries) and 11-19 (dates on the SKILL.md benchmark table). Those dated the claims. This one schedules the sources the claims rest on, and it uses a column that already exists.

2. **Give the SOURCES queue an age limit: the benchmarks' own papers have been queued for 37 days while 208 of their grader files were mined.** The 8 `queued` rows are all from the 10-19/10-20 intake. They include **S020 (the Terminal-Bench paper), S021 (Toolathlon) and S022 (LiveBench)**, plus the interval-estimation primaries S031/S032 (Wilson, Brown–Cai–DasGupta) and S035 (prediction-powered inference). Those are the claims a model-evaluation lane is asked about first. The same goes for the interval papers that `attribution-interval-calibration`-style work relies on.
   Proposal: a rule that a `queued` row older than 30 days must be mined or rejected with a reason in the next round, plus a lint warning that lists the stale ones. The first run would be cheap: six papers, where the mined S020 is checked against the existing `tb2-grader-class-census.md` (does the paper's validation claim match the 89-task grader census?). This is not the 11-22 TB2 stop rule, which capped new knowledge notes by bytes. This one closes a backlog of primary sources that the lane already chose and never read.

## 2. Suggestions (new; none repeat 10-18 → 11-25)

1. **Record which model ran each seat. A model-evaluation lane can't currently attribute any finding to a model.** Round 17 stopped before dispatch because of model routing. `.ufo/round-17/route-blocker.json` lists the missing role→alias bindings: reviewer was `@m_mid` but needed `@m_grok` (29 members), critic was `@m_strong` but needed `@m_grok`, connector was `@m_mid` but needed `@m_antigravity`, and `m_antigravity` had no `@m_zfl` fallback. The binding was clearly treated as part of the experiment. After that round it stops being recorded. `.ufo/waves/round-100/w1-dispatch.json` (12 seats) has `role` for each member and `agentId: null`. It has no alias, no concrete model and no effort. `w1-results.json` entries have only `name/agent/output/note`. Neither file contains a single `@m_*` string. In `LOG.md` the last alias mention is at character 41,667 of 401,600, which is the r17 era. So 80+ rounds of seat findings can't be split by model. That split is the lane's own subject, and 2026-11-22.md §2.2 found model selection and routing at only ~4.5% of knowledge.
   Proposal: `w*-dispatch.json` members carry `{alias, resolved_model, provider, effort}`, read from the effective `agentModelOverrides` at dispatch time. That is the same source r17 read, hashed the way r17 hashed `config.yml`. Each `w*-results.json` entry echoes those fields, and a results file whose fields don't match the dispatch fails the wave. This is cheap to add, and every later round becomes a model×role observation without extra seats. It differs from 11-23 §2.3 (`battery_run.py`, live endpoint measurement). That proposal adds a new instrument. This one stops throwing away data the fleet already produces.

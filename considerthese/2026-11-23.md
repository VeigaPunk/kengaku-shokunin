But `grader.py` `main()` (line 5664) wires exactly four evidence trees, r8, r9, r11 and r12, and SKILL.md §Hermetic grader (line 545) admits it "replays four" trees, 733 checks, unchanged since round 14. So a stranger who follows SKILL.md gets a green 733/0 that says nothing about rounds 13–100. This also corrects my own record: several earlier proposals (10-18 `check_battery_attrib`, 11-19 `check_selection_table_age`, 11-20 `check_skill_budget`, 11-22 `check_knowledge_mix`) assumed `grader.py` is the general lint. It is a frozen evidence-replay gate, and bolting repo lints onto it would blur what its 733 means.
   Proposal: add `plans/VERIFY.tsv` with one row per round: claims file, verifying command, expected exit code, and last-passed date. Add a stdlib `verify_all.py` that runs every row and prints `COVERED n / UNCOVERED m` with the uncovered rounds listed. It should exit nonzero on any failing row, and also on any claims file with no row. Then reword SKILL.md lines 17 and 366 to name `verify_all.py` as the entry point and `grader.py` as the r8–r12 replay layer. Structural lints would live beside it (for example a `lint.py`), not inside `grader.py`. This differs from the 11-16 idea, which only merged the per-round `*_c1_replay.py` scripts into one library. That idea is about how the code is shared. This one is about whether each claim has a check at all.

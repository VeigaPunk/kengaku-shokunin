### Defect 1 (moderate — the recurrence statement is not fully honest) — line 36, Mistakes row 2, "captured-by" column

The row states the recurrence itself honestly (the claims header self-discloses at `plans/round-38-claims.md:8-15`; `control-c2-skip.txt` committed at the freeze carries `P10 DEFECT fresh probe output is not byte-equal to the receipt`; `git cat-file -e e0a37853:corpus/evidence/round38/build-pmars-probe.txt` → rc 128 — all three re-verified). But its characterization of the prior round's fix is wrong:

> line 36: "round 37's fix (re-pin and re-run every counter run) does not prevent the ordering, it only makes the discarded run harmless"

The cited row, `corpus/lessons/round-37.md:42`, fixes the class with **two** moves; the lesson quotes only the first. The second is an explicit rule forward, verbatim from :42's fix column: **"Rule forward: a control that executes a frozen instrument keeps the run as a receipt."** Round 38 violated exactly that rule — `plans/round-38-claims.md:10-11`: the control-time run's "output was discarded unread; it is not the first recorded run and is not evidence". Had the rule forward been followed, the control-time execution would itself have been the recorded run (kept and committed with the control at the freeze), and the recurrence — an execution preceding the first recorded run — could not arise. So the lesson (a) omits the violated half of the fix it cites, and (b) asserts that fix "does not prevent the ordering", which is false for the rule-forward half. Net effect: the lesson reframes a broken rule as an insufficient rule, which is the difference between "the fix didn't cover this" and "the fix was not followed" — precisely the honesty the recurrence statement was supposed to carry. The new round-39 ordering rule it proposes ("built only after the first recorded run lands, or with `--rerun` off") is a different, weaker mitigation and is offered without noting the available, violated one.

Evidence: `corpus/lessons/round-37.md:42` (fix column tail, quoted above); `plans/round-38-claims.md:10-11`; receipts file §"Key cross-references".

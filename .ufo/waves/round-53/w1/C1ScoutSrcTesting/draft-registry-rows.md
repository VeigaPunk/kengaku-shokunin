## Per-source bearing on "tests that pass if the named artefact merely exists" in a benchmark grader

- S901 — yes, at the definitional level: "a procedure that distinguishes between the correct and incorrect behaviors of the
  System Under Test (SUT)" — an existence-only assertion does not distinguish. Caveat: the survey never names
  file-existence checks or benchmark graders; it supplies the taxonomy, not the instance.
- S902 — yes: "statements are covered but their consequences not asserted upon" is the presence-only gap in industrial
  terms, measured by mutation analysis.
- S903 — yes: "test suites with no assertions still detect a significant fraction of the mutations (43 % on average)" —
  presence-only assertions sit just above assertion-less suites, whose passes already prove almost nothing.
- S904 — yes: the oracle gap is a direct metric; the same archived text continues "Naive, automatically-generated tests
  that cover code without strong assertions straightforwardly produce positive" (gap).
- S905 — yes: "Oracle strength is high on average but uneven, with weaker assertions for object return property values
  and exceptions." — per-assertion-strength measurement with crash kills excluded.
- S906 — yes: "some test suites achieve 100% coverage but only 4% mutation score" — passing tests measured to detect
  almost no behavioral change.
- S907, S908 — no (rejected above, with flips).

Problem

tests/conftest.py gives code under test a writable path to the verifier's per-test verdict. In pytest_runtest_protocol, the verifier creates a pipe and forks. The child closes only the read end, drops privileges, and imports drift_monitor before the test body runs. Submission-controlled import-time code still holds the pipe's write end.

The parent treats the first byte it reads as the verdict. A submission can find writable pipe descriptors and write the pass byte during import. The forged byte reaches the parent before the child writes its real result.

A package with failing behavior can therefore be reported as passing for every test. We reproduced this with the original six defects left in place. All 11 tests were reported as passing.

Requested change

Do not expose the pass or fail transport to any process that imports or executes submission code. A trusted supervisor should determine the verdict from data it checks itself, while the submission process has no writable verdict channel. Add a regression test that uses a deliberately failing package which writes a pass byte to inherited pipes at import time, and assert the suite fails.

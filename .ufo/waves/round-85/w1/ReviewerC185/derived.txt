PYTHON SEMANTICS RELIED ON
  S1. Set intersection `&` selects elements x of soln_tuples for which an
      element y of data_tuples exists with `x == y` and (as the fast path)
      hash(x) == hash(y). Cardinality is a count of DISTINCT soln tuples
      matched; it is not a row comparison and it cannot exceed |soln_tuples|
      = 8.
  S2. json.load maps a JSON number with a fractional part or exponent to
      `float`, and a bare integer literal to `int`.
  S3. int/float equality: `10 == 10.0` is True and `hash(10) == hash(10.0)`
      in CPython, so the tuple `("testword02", 10)` is equal to
      `("testword02", 10.0)` and set intersection COUNTS it. Integral
      solution values (10.0, 25.0, 42.0, 50.0, 75.0, 99.0) accept JSON ints;
      non-integral ones (99.99, 0.5) only accept the exact float.
  S4. str vs float: `"10.0" == 10.0` is False and their hashes differ, so a
      tuple carrying a JSON string value never matches a float solution
      tuple. All eight string-valued rows therefore score 0.
  S5. Set construction deduplicates: repeated identical rows collapse to one
      element before the intersection, so 16 duplicated rows can only
      contribute the distinct matches.
  S6. Extras: data tuples absent from soln_tuples contribute nothing; the
      intersection is asymmetric in that direction. Extra non-solution rows
      cannot raise or lower a score built only from solution tuples.
  S7. Judgement boundary: `assert score > 6` is STRICT. score 7 passes,
      score 6 fails (AssertionError, message "Did not load data correctly").

# ProvenanceAttackR72

## Attack 1 — caller `PYTHONPATH` stub

**Expected:** If caller-controlled `PYTHONPATH=/app/stub` survives the sandbox boundary, importing transformers resolves to a raising stub; the witness must instead show the sandbox's `/venv` module. **Observed:** scratch-only wrapper around `stage_case` planted `app/stub/transformers.py` raising `RuntimeError`, set caller `PYTHONPATH` to the scratch stub path, and ran K1 via `run_case` under the assigned port lock. Command: `ATTACK=stub python3 /fast/scratch/hyaku/kengaku-r72/ProvenanceAttackR72/attack.py`; rc 0. Receipt excerpt: `derived=PPPP`, `sandbox_rc=0`, `canary=ABSENT`, `transformers_file=/venv/lib/python3.13/site-packages/transformers/__init__.py`. **Verdict:** This injection did not survive: `bwrap_argv` overwrites PYTHONPATH with fixed `/venv/lib/python3.13/site-packages`, and the app stub is not imported.

## Attack 2 — cwd shadow and import search order

**Expected:** A module or site customization in `/app` could shadow the intended transformers import if `/app` is first on `sys.path`. **Observed:** Scratch-only harness instrumentation printed the staged sandbox's `sys.path`, with a raising `/app/transformers.py` planted: `['/probe', '/venv/lib/python3.13/site-packages', '/home/vgpnk/.local/share/uv/python/cpython-3.13.16-linux-x86_64-gnu/lib/python313.zip', '/home/vgpnk/.local/share/uv/python/cpython-3.13.16-linux-x86_64-gnu/lib/python3.13', '/home/vgpnk/.local/share/uv/python/cpython-3.13.16-linux-x86_64-gnu/lib/python3.13/lib-dynload']`; result `derived=PPPP sandbox_rc=0`, `transformers_file=/venv/lib/python3.13/site-packages/transformers/__init__.py`. Command: `python3 /fast/scratch/hyaku/kengaku-r72/ProvenanceAttackR72/path.py`; rc 0. The earlier `ATTACK=shadow .../attack.py` run also returned K1 `PPPP`, rc 0, with the same `/venv` path. `sitecustomize.py` in `/app` was planted in the staged case; it did not produce its marker: `/app` is not on the runner's `sys.path`. No probe code was edited; these were scratch-only wrappers/staged inputs. **Verdict:** Neither cwd `transformers.py` nor cwd `sitecustomize.py` shadowed this harness import. The first actual `sys.path` entry is `/probe`, not `/app`; fixed `PYTHONPATH` entry `/venv/.../site-packages` follows.

## Attack 3 — allowlist and environment-variable injection

**Observed:** `ENV_ALLOW` is exactly: `PATH=/usr/bin:/bin`, `HOME=/app`, `LANG=C.UTF-8`, `PYTHONPATH=/venv/lib/python3.13/site-packages`, `PYTHONNOUSERSITE=1`, `PYTHONWARNINGS=ignore`, `TMPDIR=/tmp`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`. Every value is a fixed literal; none is derived from a caller variable or points to a caller-controlled host path. `/app` is the sandbox's staged-writable tree, but the executed runner's first `sys.path` item is `/probe`, so its cwd is not an import entry. `TMPDIR=/tmp` is sandbox tmpfs. In the K1 attack driver, caller `BASH_ENV=injected-bash`, `PYTHONSTARTUP=injected-startup`, `PYTHONHOME=/bad/pythonhome`, plus the `PYTHONPATH` stub were set; observed sandbox `env_keys=HF_HUB_OFFLINE,HOME,LANG,PATH,PWD,PYTHONNOUSERSITE,PYTHONPATH,PYTHONWARNINGS,TMPDIR,TORCHINDUCTOR_CACHE_DIR,TRANSFORMERS_OFFLINE`, `canary=ABSENT`, and `transformers_file=/venv/lib/python3.13/site-packages/transformers/__init__.py`. `BASH_ENV`, `PYTHONSTARTUP`, and caller `PYTHONHOME` were absent; `/venv/bin/python3` ran successfully. Command: `ATTACK=sitecustomize python3 /fast/scratch/hyaku/kengaku-r72/ProvenanceAttackR72/attack.py`; rc 0; K1 `PPPP`, sandbox rc 0. **Verdict:** No caller-data-bearing allowed value or tested environment-variable injection was observed. The `env_keys` set includes `PWD` and `TORCHINDUCTOR_CACHE_DIR` in addition to the nine allowlisted names; their values are not reported by the probe. `PWD=/app` is sandbox-local, and this test observed no influence on import resolution. This is a residual visibility gap rather than evidence that those values carry caller data.

## Attack 4 — write into the bound venv

**Expected:** If the provenance target were writable, a staged/local module could be installed in the bind and satisfy the `/venv/` prefix check. **Observed:** One-command sandbox write check (scratch helper invokes the probe's `bwrap_argv`, replacing its harness command with `python3 -c` writing `/venv/lib/python3.13/site-packages/.r72-write-test`): `python3 /fast/scratch/hyaku/kengaku-r72/ProvenanceAttackR72/readonly.py`; rc 0; stdout `OSError:[Errno 30] Read-only file system: '/venv/lib/python3.13/site-packages/.r72-write-test'`; stderr empty. The argv binds `VENV` to `/venv` with `--ro-bind`. **Verdict:** The bind is read-only; installing a new module there from the sandbox fails. A direct equivalent one-command check is `bwrap ... --ro-bind /fast/ComfyUI/.venv /venv ... /venv/bin/python3 -c "open('/venv/lib/python3.13/site-packages/.r72-write-test','w').write('x')"` (expected `EROFS`).

## Overall

No tested provenance attack succeeded; the K1 sandbox loaded the venv's transformers and passed all four legs. No claim is made that the complete nine-case predicate was re-run. One instrumentation run initially failed before executing the sandbox because the scratch read-only helper replaced the last two bwrap argv elements and produced `bwrap: Unknown option -c` (rc 1); corrected to preserve the Python executable, the write attempt above produced the reported read-only result. No tools were installed.

   still contain `--skip-selftest`, so `tip-flag-absent=False`. The "green at tip" premise does not hold.
2. Pin-count conflict: the C1 leg L8 needs a `plans/counter-pins-r91.json` entry for the probe; adding one
   makes the default checker print `PINS checked=18`, which the C2 M9 literal `PINS checked=17` rejects.
3. Commit-C conflict: flipping the ledger turns the round-91 counter red on the M7 tip leg
   (`DEFECT L7 ledger ... executed_total=36`, rc=1), so R92-C2 M7 fails at the tip after C.
4. Gate v3 default predicate path recurses: the selftest child is not in child mode because the parent argv
   lacks `--selftest`; the child re-runs the full battery; the outer run dies with TimeoutExpired after 600 s
   and prints no PREDICATE line. `--selftest` alone is 10/10 green at the control.
5. Gate at B2 (no triage rows): `freeze=refused pending=1 malformed_unresolved=1` from the schema-invalid
   R82-F1 row at line 125 (not a chain), plus `check-failed R82-V8`. The predicted `freeze=admitted pending=0`
   is not reached at B2.
6. R82-V8 is clone-path dependent inside the gate: `run_check` passes only PATH/HOME/LANE, so SHOKUNIN_ROOT is
   dropped and `origin.parent` (the gate worktree's parent) is used. With SHOKUNIN_ROOT set the check is `CHECK v8 ok`.
7. Packer slot budget 36 is non-binding on the frozen inputs: 36 and 40 produce identical plans for all 19
   case plan files, so the receipt observation block cannot detect it; only the pin/stamp legs can.
8. The bs-probe stamp always reports `WORKTREE dirty`: `sh()` returns the literal `absent` for empty
   `git status --porcelain` output, and the stamp compares against `""`. No counter checks this field.

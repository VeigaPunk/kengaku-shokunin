## Second-order trace (contradictions stated, not smoothed)

1. **Design contradiction across lanes on (b).** The sibling fleet's settled discipline is *refuse worktree as instrument source; execute from rev bytes* (kaidoku round-46 gate.py:188-191, round-48 record2.py:64-65; kama `--mode worktree` exits 2; kotodama linked-worktree refusal). Kengaku's v3 gate inverts it: checks *execute inside* a worktree-at-rev. Both attack the same defect class (worktree-vs-rev byte confusion) with opposite mechanisms. This is a genuine contradiction of mechanism, not a scoring difference; it also means "reuse a sibling runner" is unavailable — the capability is novel to the lane.
2. **The frozen M11 runner writes lane git metadata during measurement.** `plans/round92_burndown.py:291-294` runs `lane.git("worktree", "prune")` and `lane.git("worktree", "add", "--detach", str(wt), rev_sha)` with `wt = work / "rev-worktree"` under `--work`, and :308 removes it — so the checkout lives in scratch but the worktree REGISTRATION lives in the lane's `.git/worktrees/<id>` for the duration of the predicate. Read-only for refs and index, but it mutates lane git metadata mid-measurement — the same surface this round's seat bounds protect. This is the frozen counting command's own behavior: reported per the freeze discipline, never repaired in place.
3. **(d) equivalence trap.** kagi's external controls TSV satisfies "external expected-rc table" but not "ledger-checked pin"; collapsing the two would erase exactly the M9 tamper arm (`expectations-tampered` → `DEFECT SETUP … rc 2`). They are kept as separate rulings above.
4. **Clone-form dependency (for any future v4).** M10/M6 resolve `shokunin.conf` via `SHOKUNIN_ROOT` or `lane.root.parent` (`plans/round92_burndown.py:284-285`, :288-289). A scratch-clone-based runner would resolve `lane.root.parent` to the scratch dir, so `SHOKUNIN_ROOT` must be exported; absent it, the gate fails closed (`CouldNotEvaluate`) — safe, never silent-green.

## Proposed move (one, bounded, compatible synthesis)

**Route a disclosure finding (report/routed-row channel only; no frozen byte changes):** kengaku's M11 worktree-at-rev execution is novel in the fleet, but its registration form (`lane.git("worktree", "add"/"prune"/"remove")`) writes lane git metadata during every measured run; the fleet already contains a compatible, precedent-backed alternative form — kaidoku round-43's clean `--shared` clone checked out at REV with cleanliness bound into the receipt (`tools/round-43/c2-score-r43.py:121-122`, :144-146). A future gate version (v4, new frozen predicate, B2-style disclosed before any scoring) could materialize the rev worktree from a scratch `--shared` clone of the lane, making the measured run read-only against the lane end-to-end.
- **Affected axes:** operability (removes measurement-time lane-git-metadata mutation; aligns the gate with the fleet's own lane-guard seat bounds) and, secondarily, calibration (a clone-form runner cannot collide with a concurrent seat's worktree registrations in the same lane repo). Coverage untouched: the executed_rows/cases/legs arithmetic reads the same rev bytes either way.
- **Harms none:** it is future-work routing, not an edit to the frozen v3 predicate, targets, or kill rules (frozen-text discipline respected; the in-tree-pin L0 residual stays disclosed, not closed).
- **Risks:** (i) selftest cases that assert lane-side worktree behavior would need their own red-green update in that future round; (ii) `SHOKUNIN_ROOT` must be exported in clone runs (trace 4) or M10/M6 fail closed; (iii) the move is only sound as a NEW frozen predicate with disclosure before scoring — landing it silently would be exactly the re-freeze defect class this round routes around.

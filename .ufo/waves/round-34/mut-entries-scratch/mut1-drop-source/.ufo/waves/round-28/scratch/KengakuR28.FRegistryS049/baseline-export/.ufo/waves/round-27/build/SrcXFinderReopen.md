# S044 reopen — xFinder extraction comparisons

**Question / axis:** novelty; what xFinder compares and how that bears on C1. Public source opened 2026-10-21: https://arxiv.org/abs/2405.11874 and https://arxiv.org/pdf/2405.11874v3. Current arXiv record says last revised 2025-02-25, v3; it is published as an ICLR 2025 conference paper (PDF p.1); v4 URL returned 404.

## Findings

- **Extraction methods (§5.1, Tables 1–2; PDF pp.7–8):** three framework RegEx modules—OpenCompass, LM Eval Harness, UltraEval—are baselines; learned xFinder extractors are the comparison methods. Table 1 reports three RegEx baselines versus a subset of xFinder models on KAF test. Table 2 adds GPT-4 as extractor and two xFinder models on KAF generalization. Appendix D.2, Tables 22–23, reports extraction accuracies for all 19 fine-tuned xFinder model variants. These are not a controlled first-match/last-match sweep: the paper does not specify each framework's exact regex rule/version or isolate rule-level variants.
- **Judgment comparisons are separate (§5.2, Table 3, PDF p.8):** framework methods, PandaLM, JudgeLM variants, GPT-4-as-judge, and xFinder are compared on judgment accuracy. Do not count judges as extraction policies. Table 4 reports an accuracy gap (judgment minus extraction accuracy), not extractor agreement.
- **Response populations:** KAF test = 4,961 items, LLM responses from 10 models across 8 evaluation tasks (§4.1, Table 13–16, PDF pp.6,17); KAF generalization = 4,482 items from 8 models on 11 entirely new evaluation tasks (§4.1, Tables 17–20, PDF pp.6,18). For each §5.1 table, methods are evaluated against the same named KAF set/response population; test and generalization are different populations. §5.3 evaluates 10 LLMs over 14 task datasets and compares the two selected xFinder models with the three frameworks' RegEx methods; setup says they replicate only the RegEx methods and standardize other settings (§5.3, PDF pp.9–10). The paper does not explicitly document per-record pairing of saved §5.3 responses across arms.
- **Metric:** Extraction Accuracy = fraction of correctly extracted key answers (against KAF key-answer labels); Table 3 Judgment Accuracy = fraction of correct judgments, using human-annotated results as ground truth; Table 4 Accuracy Gap = the difference between those accuracies. Appendix B.2 (PDF p.19) says each item had two annotators and disagreements were rechecked; no inter-annotator-agreement coefficient or pairwise extractor verdict-agreement/flip metric is reported. §5.3 adds accuracy results and rank comparisons (Figure 4, PDF p.10), but no rank-correlation coefficient.
- **Useful text evidence (quotes each <25 words; access date 2026-10-21):**
  - “The comparison metric is extraction accuracy, defined as the proportion of correctly extracted key answers relative to the dataset size.” §5.1, PDF p.7; https://arxiv.org/pdf/2405.11874v3
  - “we replicated only the RegEx methods on each framework and ensured consistency in other settings.” §5.3 Setup, PDF p.9; https://arxiv.org/pdf/2405.11874v3
  - “Such disparities in rankings indicate the unreliability of RegEx methods within mainstream evaluation frameworks” §5.3 RQ1, PDF p.10; https://arxiv.org/pdf/2405.11874v3
  - “If so, extract this corrected or modified answer as the final response.” Appendix F.4, Figure 32, PDF p.43; https://arxiv.org/pdf/2405.11874v3. This is a semantic correction-aware rule for xFinder, not a simple regex match-order policy.
- **C1 relationship:** classify as a *narrower instance / different operationalization* of the published extraction-method-dependence construct, not a replication and not distinct in kind. xFinder already compares framework extractors on benchmark responses and shows accuracy/ranking outcomes depend on extractor. C1 narrows to isolated rule-based parser policies over the frozen lane responses with grader and truths fixed, and measures verdict agreement/flips versus the stored verdict plus pass-rate shifts; xFinder does not report that paired verdict-agreement measurement. No xFinder model/data/metric is reproduced by C1. Thus the broad construct is prior art; the exact C1 measurement remains unobserved in this paper. This supports the pre-registration's “published in kind” reading without claiming xFinder measured C1's exact estimand. See `plans/round-27-claims.md:21-57,73-78`.
- **Comparability caveat:** Table 2's OpenCompass overall 0.7438 reproduces as the weighted mean of only its reported alphabet (n=1,280) and math (n=640) strata, 1,920/4,482 items; xFinder-qwen1505's 0.9342 reproduces across all four strata and 4,482 items. The paper does not explain `/` or denominator handling. Treat overall cross-method comparison as subset-denominator-sensitive. Footnote 5 (PDF p.8) attributes lower RegEx accuracy on generalization versus test to restricted versus non-restricted prompts, while Tables 16/20 (PDF pp.17–18) list only non-restricted prompt configurations; unresolved reporting inconsistency.

## Self-improvement suggestions (proposals only; nothing acted on)

1. **Treat scratch as untracked, content-addressed cache, plus a carrier-aware pre-landing scan.**
   Measured on the `1f3b0f1` tree: 6872 files and 444 MB of the repo's 479 MB of tracked blob bytes sit under
   `.ufo/waves/*/scratch/`, and 374 MB of that is duplicate blobs (1077 groups). For example, the same 3.88 MB `v2-out.json` is
   committed five times under `round-29/scratch/falsify/`, and two arXiv PDFs (10.7 MB and 9.1 MB) sit in
   `round-28/scratch/FBoundaryReleaseScope/`. That same habit is how r29 committed a credential-bearing upstream
   `env_config.py`, first as a loose file and then compressed inside a tracked `.whl`, and the loose-path removal missed the
   archive copy (`corpus/lessons/round-29-source-copy-containment.md`). Proposal: `scratch/` goes in `.gitignore`. Each fetch is
   recorded in an append-only manifest (URL, fetch time BRT, sha256, size, licence), not stored as bytes. A pre-landing check
   recursively opens zip/whl/tar members, flags vendored third-party modules and secret-shaped content by blob identity, and fails
   closed, with red/green fixtures built from the r29 wheel identity (`81cf52de…`). This is about artifact hygiene and safety, which is
   a different problem from the 10-19 wip/ quarantine for unadmitted claims.

2. **Turn the WebArena static audits into a measurement of evaluator error.**
   r28 (`plans/benchmark_spec_audit.py`: 812 tasks, 27 site/evaluator strata, 16 audited deterministic cases, 651 page
   targets) and r29 (`plans/config_projection.py`: 2436 projections, 1435 provenance rows) now let the lane *parse* the benchmark
   exactly, but both say outright that they're "not task validity, model ability" (`LOG.md` §Round 28). Proposal: freeze a small,
   pre-registered population of synthetic agent final states/answers per evaluator type (string_match exact/must_include/fuzzy,
   url_match, program_html), each with a hand-labeled true outcome. Then run WebArena's evaluator *logic*, reimplemented offline
   from the pinned spec as r29 already does with the generator, and report false-pass/false-fail rates per stratum with CP95
   intervals (the r25 interval tooling). That's a model-relevant claim with a falsifiable number. It also has a natural prior-art
   foil (WebArena-Verified), which is exactly the preflight 10-21 #2 asks for.

3. **Make crash recovery resumable instead of heroic.**
   r29's host crash killed 23/64 build seats, including all three executors. A replacement L1 had to reconstruct the
   build from landed reports (`.ufo/waves/round-29/build-dead-seats.json`), and r28 needed a manual "parent-requested snapshot"
   commit (`39a66fe`). Deaths are recorded faithfully but never replaced (r27: 19+21 unreplaced). Proposal: each seat writes
   an append-only journal (`dispatched / started / report-path / sha / done`) to a single wave file that is committed on a timer. Add
   a `resume_wave` step that redispatches only seats with no `done` row, under a fixed per-wave replacement budget, and record
   replaced versus abandoned seats as first-class scorecard fields. Lost coverage then becomes a number instead of a prose caveat.

## Three most important lessons / gains (2026-10-19 → 2026-10-22)

1. **A safety near-miss: an absence check has to look inside archives, and git history is still exposed.**
   During r29 falsification, a downloaded upstream WebArena module containing credentials (`webarena/browser_env/env_config.py`) was
   committed into tracked scratch. The first cleanup proved that five loose paths were absent. A non-author opaque-archive
   check then found the identical blob (`81cf52de…`) still compressed inside
   `.ufo/waves/round-29/scratch/falsify/FCritNovelty/fetch/libwebarena-0.0.5-py3-none-any.whl` at `6a2c2df`. The current-tree copy
   was removed in `1f3b0f1` without printing or using the values. The lane is explicit that this is **not** a history purge or
   a credential rotation, and that other carriers are unresolved "under the operator hold" (`LOG.md` §Round29 containment).
   That's honest bookkeeping, but it's João's decision whether those credentials need rotating and whether history should be rewritten.

2. **Coverage moved onto benchmark-spec ground, with three new reproducible capabilities and honestly held scores.**
   r27 added fixed-response extraction-policy comparison (15712/1089 over five policies, independent replay in
   `plans/fixtures/r27/independent_policy_recheck.py`). r28 added the pinned WebArena task-spec audit (812/812 IDs, selftest
   21 → 67 after falsification) and a literal source-reference checker that went red on S038/S050 and green at the final tree. r29 added

   correct given the stated prior art and no-validity limits, but it means these are observability gains, not score gains. Spending
   roughly 130–140 seats per round for held scores is the strongest argument for suggestions 2 and 3 above.

3. **Measuring the actual landing commit keeps catching real instrument bugs, and r29 closed the gap.**
   The landing-time bar from r26 (Q13) is paying off. r28's admission `df33fc8` exited 1 on both the Gate and the census. That exposed
   a legacy `state_check.py` scope bug where round-26 `revision_text` ran to EOF and swallowed round-28 score prose. It was fixed with a

   falsifiers found `python -O` silently stripping the selftest, `--json` reordering tasks, and value-normalization and
   category mutants surviving. r29 then landed `6baa309`, whose tree is byte-equal to the pre-landing trial tree `33d75cc`, so the
   measured tree and the admitted tree are now provably the same object. Lesson: a check run on the real artifact beats a green
   prospective sandbox, and trial-tree equality is the cheap way to get that before pushing. All of this is still author-side; non-author
   closure for r27–r29 is pending.

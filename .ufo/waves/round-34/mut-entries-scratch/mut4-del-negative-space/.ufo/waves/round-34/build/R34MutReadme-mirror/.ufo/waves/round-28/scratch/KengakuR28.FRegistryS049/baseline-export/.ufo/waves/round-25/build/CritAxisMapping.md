# CritAxisMapping — r25: novelty→coverage mapping critique

Scope: `plans/round-25-claims.md:14-19` vs `PROTOCOL.md:505-518` (Fleet-2), `AXES.md`, `SCORECARD.md`, `MISSION.md`, `LEARNING.md`. Read-only seat.

## F1 — Mapping placement fails the Fleet-2 row rule
`PROTOCOL.md:514-516`: a non-`AXES.md` axis name (`novelty`) "is worked only if its row carries its mapping to one of the six axes… in the same row". The mapping lives only in `plans/round-25-claims.md:14-19` — a plans file, not the SCORECARD row. The current novelty row (`SCORECARD.md:610`) carries no mapping, and the only in-SCORECARD novelty definition (`SCORECARD.md:13-21`, "the mapping in this file is the definition of record for this repo") is a sub-axis rubric, not a canonical-axis mapping. A non-author re-deriving at the row sees no `novelty → coverage`. The round-25 novelty row must carry the mapping inline or the row violates Fleet-2 on its face.

## F2 — The mapping is invoked asymmetrically (double-count shape)
The claims file applies it for claim dedup only: `:18-19` "this round makes no separate coverage claim (two claims on one canonical axis would be one claim)" — correct under `AXES.md:31-32`. But `:9-12` scores and tie-breaks novelty and coverage as **two distinct** axis lines ("novelty 7, tied with coverage 7"; "a coverage move cannot change its number, novelty can"). Same-axis-for-dedup, different-axes-for-scoring is coherent **only** under a nominal mapping (label-level alias for the distinct-axes rule, scores/rubrics stay row-local). That reading is never stated. Under the identity reading a re-deriver gets two contradictory canonical-coverage numbers: capped 7 (`SCORECARD.md:613`) and `novelty+1 → 8`. Either the mapping is nominal (then `:18`'s parenthetical is wrong — two differently-scored rows on one canonical axis is precisely the "one claim" case) or it is identity (then the `SCORECARD.md:613` cap binds the claim's score and `:12` "novelty can [change its number]" is false).

## F3 — Coverage is the wrong canonical target; calibration is unconsidered
`AXES.md:12` coverage = "fraction of the domain's real surfaces the skill governs (repo paths, tools, edge classes)". C1's construct (`plans/round-25-claims.md:23-26`) is the *existing* instrument's own accuracy/per-leg intervals — better-governed measurement of an edge class already held since r21 (`SCORECARD.md:487-517`), not a new governed surface. Re-verdicting stored point verdicts against recomputed state is verbatim the calibration signal: `AXES.md:15` "SCORECARD entries match observed repo state" — and C2 (`:70-73`) is exactly that operation. Counterexample: map `novelty → calibration` (semantically the better fit; `LEARNING.md:86` discernment↔calibration; the file's own `LEARNING.md` expansion-trend cite, `claims:16`, actually points novelty at the expansion pair coverage+adjacency — consistent) and C1+C2 collapse to one claim under `AXES.md:32`. Choosing coverage preserves two claims; choosing calibration preserves semantic truth. The file never weighs the alternatives — the mapping reads as chosen to keep the claim count, not because the construct is a governed surface. `MISSION.md:24` assigns the lane `novelty + calibration` — under a calibration mapping the round's two claims still satisfy the lowest-axis rule (novelty 7 is the lowest owned row), so nothing in the contract forces coverage.

## F4 — Seventh axis: no, seventh *row* scored on one canonical axis: yes
"Novelty" does not silently become a seventh axis — `:17-18` explicitly denies it. The actual defect is dual authority on one canonical axis: two rows (`novelty`, `coverage`) carrying different rubrics (`SCORECARD.md:244` vs `:247`), different caps (power-ask vs unresolvable-surface), and different scores, both claimed to live on canonical coverage. AXES.md:37-38's retirement/split machinery is the designed mechanism for sub-axes; the mapping route silently creates the same structure without it.

## F5 — Rubric ambiguity under the mapped claim
If the mapped claim is scored under the *canonical* axis's rubric, C1 verifies as a coverage no-op: `SCORECARD.md:247` requires index/PROVINCE surface movement, which `claims:59-66` never proposes. If scored under the legacy rubric (`:244`), the mapping is decorative — nothing canonical moved. The file picks neither; a judge cannot re-derive which rubric governs.

## Smallest safe correction
Append one sentence to `claims:17-19` and carry the same text into the round-25 novelty row: "`novelty → coverage` is a nominal mapping for the distinct-axes rule only (`AXES.md:31-32`); the legacy row is scored by its own rubric (`SCORECARD.md:244`), the coverage row's cap (`SCORECARD.md:613`) is untouched, and no claim slot on canonical coverage is consumed or produced." This fixes F1, F2, F4, F5 without touching C1's design. F3's semantic objection survives it (fixable only by remapping to calibration, which collapses C1+C2 to one claim — a design tradeoff the planner chose; record the choice).

## Falsifiable condition
Defect stands iff, at round-25 SCORECARD write time, the landed novelty row plus the claims file lets a non-author produce **two** defensible values for the round's canonical-coverage effect (e.g., "coverage moved via C1" vs "coverage held by `SCORECARD.md:613` cap") without the row saying which rubric scored the claim. One-line test: `grep -n 'novelty' SCORECARD.md` post-landing shows a row carrying a canonical mapping that does not disambiguate rubric authority.

None.

VERDICT: The mapping is not a seventh axis but is an unstated nominal alias deployed only for dedup while coverage is the semantically weakest target — make the mapping nominal+row-local inline in the SCORECARD row, or remap to calibration and accept the single-claim round.

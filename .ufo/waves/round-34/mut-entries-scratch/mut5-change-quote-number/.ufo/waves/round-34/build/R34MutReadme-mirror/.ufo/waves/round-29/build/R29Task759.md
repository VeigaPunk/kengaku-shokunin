## Replacement-order observability (new, and a limit on the 2436 projections)

- No token is a substring of another token, and no value in any of the three profiles contains a token. Therefore
  the six replacements commute on these inputs: all **720** permutations of the order produce the same digest for
  each profile (1 distinct digest per profile, 3/3).
- Consequence: the 2436 task/profile projections **cannot witness the mandated sequential order**. Order fidelity
  needs synthetic witnesses, e.g. GITLAB value `http://g.invalid:1/__MAP__` → forward order yields
  `http://g.invalid:1/m` (later-token cascade), and GITLAB value `__MAP__` yields `"m"` forward but `"__MAP__"`
  under reversed order. So order is observable only when a substituted value contains a later token — a condition
  the frozen profiles deliberately never meet.
- Failure-not-repair boundary, synthetic in-memory probes: a value containing `"` produces
  `JSONDecodeError: Expecting ',' delimiter` (pos 48); a value containing `\` produces
  `JSONDecodeError: Invalid \escape` (pos 46). Text-level replacement can therefore invalidate the document, and the
  contract is a reported failure, not an escape repair.
- Independent oracle boundary: a separately written decoded-leaf rewriter (replace tokens in every string leaf of the
  parsed object) equals the text-level projection as objects on all three profiles (812 tasks each). It is
  equivalent only inside this benign ASCII, token-free-value domain — it would silently repair the quote/backslash
  and cascade cases above, which is why it is an oracle, not the implementation.
- Provenance unit: offsets above are raw-text **Unicode codepoints**. Raw text is ASCII, so they numerically equal
  byte offsets for this file only; the 49 `\uXXXX` escapes (294 raw codepoints → 49 decoded) mean a raw-codepoint
  offset cannot be reused as a decoded-string offset, and the label must stay codepoints.

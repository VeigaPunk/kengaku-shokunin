## C2 adversarial review

**Axis: calibration. Verdict: fails as frozen.** The proposed clean-tree exit-0 gate blocks the trivial always-red counter *in principle*: harness lines 131–134 checks `returncode == 0` and the exact `checks=8 defects=0` string before mutants. But the available harness receipt (`build/R34MutateDraft/harness-run.txt:1-5`) says `CLEAN exit=1`, N3/N4 unreadable, N7 missing correction, and does not demonstrate the required `MUTANTS total=8 detected=8`; it is not calibration closure.

**Counterexample / harness blind spot.** `round34_mutate.py:51-97` has eight fixed mutations, and lines 135–142 only count those numbered cases. It never exercises important bypasses not produced by `mutate()`: e.g. make N8 accept an index row for a missing file by checking only counts or one direction; make N5/N6 accept width variants while still detecting their one hard-coded substitutions; weaken N3/N4's required relationship while retaining the exact token strings. A mutant the harness cannot generate is invisible to `detected=8`; therefore this statistic proves only these eight exact mutations, not broad immunity to the named classes. (The frozen predicate explicitly targets the eight generated mutants, so this is a scope limitation, not by itself a falsification of that narrow predicate.)

**Class mapping is not one-to-one.** Frozen claims map four classes to N8, N2/N7, N5/N6, N3/N4 (`plans/round-34-claims.md:97-101`). Harness mapping at `round34_mutate.py:141`: M1 and M2 both expect N8; M3 expects N2; M4 expects N7; M5→N5; M6→N6; M7→N3; M8→N4. Thus classes partition mutants, but the stated heading-only, width/newline and token-co-occurrence classes each span two checks, not each mutant exactly one class as a bijection; index-vs-HEAD gets two distinct mutants on the same check. More importantly M3 inserts an empty Round 33 heading before Round 32 while N2 checks both headings, and M4 strips Round 32's content while N7 checks an unrelated ledger correction: the label/class semantics require inspecting those mutations carefully, not assuming label correctness from a detector's `N#` substring.

**Red-before provenance is insufficient / one class receipt is expressly incomplete.** The receipts contain no authenticated pre-hardening timestamp or source revision proving they predate the counter. The metadata command `stat -c '%n|%y|%W|%s' .ufo/waves/round-34/falsify/red-before/*.txt` returned mtimes on 2026-10-25 15:47–15:48 -0300; ordinary mtimes do not prove when contents were created relative to hardening. `index-head.txt:8` records `git archive HEAD`, but that is a sandbox export of HEAD, not proof the receipt itself was committed before hardening. `width-newline.txt:14` explicitly says sandbox mutations/post-mutation probes were not run; `build/R34RedBeforeWidthNewline.md:19` confirms only controls were run. `heading-only.txt:9` admits sandbox already had a Round 33 heading. `token-cooc.txt:15-20` does demonstrate its crafted false-green example, but has no pre-hardening marker. Frozen control `claims/control-c2.txt:1-9` records baseline and absent tools, not red-before receipt hashes/timestamps or commit ancestry. Consequently post-hoc generation cannot be ruled out; the width/newline receipt does not even show the requested mutation failing before.

**Smallest safe correction:** do not admit C2 on these artifacts. Require each class receipt to record the actual pre-hardening counter revision/hash, timestamped/committed before hardening, and exact mutated sandbox command/output that demonstrates the prior checker stays green; specifically rerun and capture width/newline mutations. Keep clean-tree exit-0 gate. Add at least one harness mutation for any claimed blind spot not currently generated, or state the claim narrowly as eight exact generated mutations rather than class-wide calibration.

Evidence paths: frozen predicate and mapping `plans/round-34-claims.md:71-105`; harness `build/R34MutateDraft/round34_mutate.py:51-97,120-149`; draft predicates `build/R34C2CounterDraft/round34_defects.py:54-66,88-106,131-142`; incomplete receipt `falsify/red-before/width-newline.txt:8-16`.

VERDICT: critic-c2 fails — clean-tree gate blocks always-red, but red-before chronology and width/newline evidence are unproven, and fixed mutants under-cover class variants.

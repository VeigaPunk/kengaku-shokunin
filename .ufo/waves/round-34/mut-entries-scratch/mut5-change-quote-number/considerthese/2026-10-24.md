## Self-improvement suggestions (proposals only; nothing acted on)

1. **Run the gates on every push, not only when an author remembers to.** The tree has zero files under `.github/`.
   `grader.py`, `plans/gate_timing_check.py`, `plans/grader_perturb.py`, `plans/registry_check.py` and the census
   scripts only run when a lane author invokes them, and the receipts they produce are, by the lane's own wording,
   "author-observed, never non-author closure" (`LOG.md` ~L372). Proposal: one Actions workflow that runs
   `python3 grader.py`, the `--selftest` suites and the latest census on every push to `master`, uploads stdout as an
   artifact, and pins the runner image. It is the cheapest mechanical non-author verifier available: it can't judge a
   claim, but it would have caught any landing that broke replay, and it turns "gate was green" into a third-party
   record instead of a pasted receipt. It also covers the daily `considerthese/` commits, which today nobody checks.

2. **Put an as-of date and a live/dead status on every knowledge entry, then re-probe the live ones.** `corpus/README.md`
   lists most primary sources as "Historical-unavailable" (wiki, Bailian, bench-arena, ledger), and the one entry
   built on live public APIs, `knowledge/open-model-catalogs.md` (HF `api/models`, OpenRouter `api/v1/models`), was
   probed 2026-09-28, 26 days ago. Nothing in `corpus/knowledge/` (37 entries) says when a claim was last true or when
   it should be rechecked. For a model-evaluation lane, catalog fields, model lists and benchmark versions drift on a
   weekly scale. Proposal: front-matter `as_of`, `source_status` (live/historical/dead) and `revalidate_by` per entry,
   a check that fails when a live-source entry passes its date, and a first cheap refresh of the two public catalogs
   with a schema diff against the 09-28 description. That is a freshness and coverage gain that doesn't need any
   decision from João.

3. **Measure whether the corpus answers the questions it exists for.** All current coverage numbers are supply-side
   (index parity, census counts, construct counts in `SCORECARD.md`). None asks the demand-side question: given a
   realistic question ("which open model for a 32k-context agent task on one GPU?", "is benchmark X saturated or
   contaminated?", "how many paired runs do I need to call a 5pp gap?"), does `corpus/knowledge/` plus `SKILL.md`
   produce a correct, cited answer? Proposal: freeze 30–40 questions drawn from the lane's stated scope (`PROVINCE.md`)
   before looking at coverage, grade answerable / correct / cited / stale per question, and report the gap list. This
   gives the coverage axis (stuck at 7, capped) a number that is about usefulness rather than bookkeeping, and the
   misses become a ranked backlog for new rounds.

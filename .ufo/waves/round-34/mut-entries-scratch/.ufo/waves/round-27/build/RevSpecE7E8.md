## E7/E8 semantics checked

- `JSONDecoder.raw_decode` **does accept scalars** when called at their start: observed `raw_decode("42") -> (42, 2)` and `raw_decode('"x"') -> ('x', 3)`. But E7/E8 per the table inspect only characters `{` and `[`; the instrument implements that literally (`parser_policy_compare.py:104-108, 114-120`). Thus neither policy tries a bare number/string and both return `None` for `"42"` / `"nails"` or fenced `42`. The grader contract uses only dict/list answers, so this changes extraction-`None` counts, not a possible PASS.
- `raw_decode` does **not** skip leading whitespace at its supplied index: `raw_decode('\n{"a":1}')` raised `JSONDecodeError` at char 0. E7/E8 scan forward, so `\n{"a":1}` yields `{"a": 1}`; leading space, NBSP, or BOM before `{` likewise does not prevent finding the brace. JSON-internal NBSP/form-feed is invalid; internal space/tab/CR/LF works. A decode-at-index-0 implementation would be a different policy.
- **Best-supported E8 reading: left-to-right, and once a successful span is decoded, skip every start strictly before its exclusive end.** The wording “skip starts inside an already-decoded span” supports this sequential interpretation; draft E8 does `i = end` (`parser_policy_compare.py:114-128`). Adjacent start-at-end remains eligible. Concrete crossing-span case: `raw = '["[", ",1,"]"]'`. Successful `raw_decode` spans are `[0,12)` → `['[', ',1,']` and `[2,14)` → `[', ', 1, ']']`. Reading A (skip start 2 inside prior span) returns the first value; alternative B (decode every start, then remove only spans fully contained by another) keeps both crossing spans and returns the second. A is the better-supported reading; E8's draft code implements A.

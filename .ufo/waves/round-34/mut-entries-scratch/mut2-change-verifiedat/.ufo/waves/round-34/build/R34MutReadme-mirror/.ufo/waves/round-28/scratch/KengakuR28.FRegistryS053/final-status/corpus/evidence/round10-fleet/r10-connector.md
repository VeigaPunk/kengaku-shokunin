## Adoption recommendations for kengaku `grader.py`

1. **Keep the pinned 0/1/2 split and fail closed on absent inputs.** `0` means every comparison matches, `1` means a reproducible mismatch, `2` means an input/setup failure; do not inherit kotoba's `3 = no baseline` because kengaku's CLI contract maps missing evidence to 2. This is closest to kagi's explicit 0/1/2 gate (E3) and preserves kotoba's useful distinction between drift and unavailable state (E5).
2. **Emit one stable identifier per finding and keep the mismatch summary machine-readable.** Kagi's finding tokens plus terminal clean/drift summary (E3) and kotoba's stable check IDs with `observed`/`expected` values (E5) both support triage. For kengaku, retain the pinned `MISMATCH <check-id>: stored=<x> recomputed=<y>` form, deterministic check ordering, and no extra prose that obscures the exit verdict.
3. **Make `--selftest` exercise the real grader on private temporary copies, and assert both code and finding.** Kagi's scratch selftest explicitly checks expected return code and diagnostic token (E3); transcript-scan demonstrates isolated fixture inputs including a WAL-only case (E4). Kengaku's three required mutations (stored `ok`, run-log SUMMARY number, byte in `raw`) should each produce exit 1 plus its expected check ID; successful selftest should only mean all three were detected. Kotoba's model-only `--self-test` is a useful counterexample: it validates helpers, not the full baseline comparator (E5).
4. **Keep expected values committed and independent of the recomputation.** Kagi moved from a printer to committed path/symbol expectations, and protocol explicitly says a pin is not a pin unless the expected value lives in-repo (E3, E7). Kotoba likewise stores `verifiers/baseline.json` next to its verifier (E5, E8). Kengaku's committed JSONL/runlog/Markdown evidence must remain the source of stored values; never synthesize both expected and recomputed sides from the same parsed result.
5. **Put defaults relative to the script and document the actual run in LOG/SCORECARD.** Kagi resolves sibling data from `BASH_SOURCE` and keeps baseline files beside `corpus/drift-pins.sh` (E3); kotoba resolves `baseline.json` from `Path(__file__)` and documents a reproducible command and output in LOG/SCORECARD (E5–E6). Kengaku's pinned root-level `grader.py` should follow its contract by resolving defaults from the script directory, then its LOG/SCORECARD evidence should include the invocation, observed verdict/output, and commit pointer per E7.

## Overlap rulings and ownership

- **kagi — adjacent hash/freshness gate, not evidence replay.** `corpus/drift-pins.sh` owns SHA-256/mode/line/symbol comparison of live host files against its own committed TSVs; `transcript-scan.sh` owns a live runtime DB/WAL hygiene scan (E3–E4). Neither replays kengaku's committed probe-result JSONL or SUMMARY fields. Reusing their verdict/selftest conventions is fine; a kengaku evidence grader does not duplicate their owned data.
- **kotoba — adjacent live-baseline verifier, not evidence replay.** `verify_harness_claims.py` re-observes host/harness state and compares to its verifier baseline; its 10-assertion self-test checks helper models (E5). It does not recompute round-8/round-9 evidence records. No overlap in evidence ownership.
- **kumitate — a genuine neighboring pin mechanism, but different province.** Its tracked `scripts/cite-check.mjs` validates source citations and document-declared SHA-256/git revision pins against source trees (E8); its LOG/SCORECARD describe citation re-verification and a hermetic fixture suite (E10). It is a hash/citation gate, but not a replay of committed probe evidence. Do not broaden kengaku grader into source-citation or fleet-tree verification.
- **protocol/integrator — owns any fleet-wide grader convention.** The relevant shared authority is root `PROTOCOL.md` §Evidence standard, not a sibling `protocol-shokunin` directory (E1, E7). A change limited to kengaku's `grader.py` stays kengaku-owned; if the exit/selftest/output rule is promoted to a cross-repo standard, route it to the protocol lane/integrator rather than silently imposing it on kagi, kotoba, or kumitate.
- **Other lanes / contested scope.** Kasegi and kake have no committed `.sh`/`.py` verdict script in E1. No evidence from this survey supports an evidence-replay overlap there. Kagi's separate profile-adjacent pins or any future grader coverage of shared kake/kotoba assets would require the existing owner/integrator boundary to be respected; kengaku's current evidence-only scope does not cross it (E6 output includes kagi's named `$HOME/.agents/AGENTS.md` ↔ kotoba and musketeer manifest ↔ kake ownership rows).

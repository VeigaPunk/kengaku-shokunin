# Round 33 claims review — claim-sizing rules

Reviewed frozen `plans/round-33-claims.md` at `f0b20aea` and freeze controls; counter semantics checked against lane sources. The C1 do-nothing control does **not** reach its target: it exits 1, with `rows_mined=1`, `usedby_ok=0`; the required after-state is `rows_mined=3`, `usedby_ok=1`. It does already print `entries=1`, not `entries=0` as the plan claims.

## Findings

- **C1 — inaccurate control receipt description (claims.md:57–59).** The plan says the committed control prints `entries=0`; `.ufo/waves/round-33/claims/control-nothing.txt` committed at freeze says `entries=1 indexed=1 cited_rows=3 rows_present=3 rows_mined=1 usedby_ok=0 census=ok`, `exit=1`. The control still falsifies the target predicate, but the frozen record misstates the observed control. Its target is not reached because the required rows are mined and used-by-linked, not because the entry is absent.
- **C1 — false claimed delta for S093 (claims.md:37–38, 48–49).** At freeze, the S093 row already lists `corpus/knowledge/benchmark-grader-semantics.md` in `used-by` (`corpus/SOURCES.md` row S093, commit `f0b20aea`). It therefore does not “gain” that entry this round. The required final state is concrete, but the claimed transition is inaccurate; only S103/S104 are new rows.
- **C2/N2 — counter does not measure the stated after-state (claims.md:89).** The predicate requires a `## Round 32` section “recording round 32's dispositions,” while `plans/round33_defects.py` `check_n2` (lines 91–97) passes on the heading alone. An empty heading reaches that check without recording any dispositions. Thus the counter does not enforce the frozen predicate.
- **C2/N3 — predicate and counter conditions differ (claims.md:90–92).** Predicate requires `a44b5a8` within 400 characters of `superseded`/`erratum`; `check_n3` uses `near` with width 300 (plans/round33_defects.py:100–110). It also only checks that `ae95fe0` occurs somewhere in the report, not that the erratum names it. The frozen predicate and counter therefore are not the same condition.
- **C2/N3–N6 — append-only/appendage assertions are not counter-verified (claims.md:90–99).** The predicate describes an appended erratum/addendum/correction note. The checks test co-occurrence or token presence in the current file (`check_n3`–`check_n6`, plans/round33_defects.py:100–162), not that the relevant text is appended or that old bytes remain unchanged. A rewritten report/lesson can satisfy those checks. The counter therefore does not establish the stated append-only after-state.
- **C3 — “raw response bytes” and re-derivation overstate the verifier (claims.md:117–118, 122–129).** For an oversized OpenRouter response, `catalog_probe.py` stores a synthesized envelope containing the first object and `observed_models`, then `verify()` takes the count directly from that envelope (`plans/catalog_probe.py:99–115, 178–188`). The count is not re-derived from the raw response bytes. This disclosed envelope path is incompatible with the predicate's claim that the bounded raw response bytes are committed and every number re-derives from those raw bytes.
- **C3 — live-probe authenticity is not established by the claimed verifier (claims.md:122–140).** The verifier hashes the supplied files and checks receipt/text agreement; the digest is not evidence that a capture came from the live endpoint. A fabricated, internally consistent raw/envelope + digest + receipt can satisfy offline checks. In particular, the kill-rule absolute “no fabricated bytes may ever satisfy `--verify`” (line 138) is unsupported by the mechanism. This is a universal assurance without an enumerating/authenticating counter.

## Checks satisfied / residual risk

C1's frozen `adoption_check.py` enforces expected source-ID identity, distinctness, `opened` date, index-row count, mined status, used-by and census; the additional C1 verifier checks content-specific literals. C2's six-check total is explicitly enumerated and is a mismatch-count claim, not merely an assertion. Kill rules are written before the data section for all three claims (C1 lines 60–67, C2 lines 104–107, C3 lines 136–140). C1–C3 each have a single quoted frozen predicate sentence. C3's control exits 1 with `raw=absent`; C1's target also remains unreachable despite the existing draft.

C2/N1 compares filesystem files with `git ls-files` (plans/round33_defects.py:68–88), so it demonstrates index tracking, not necessarily committed-tree membership. That is a residual risk if “committed” is intended; the predicate itself says “git-tracked.” No check was run as part of this review.

## 4. Findings this draft encodes (each with its receipt line)

1. **A static file on :8080 with no git repository, hook or push passes.** `verify.sh:49` runs the
   expect script and never reads its status; only the HTTP status of the first request and the body of
   the second can fail the grader. Receipt: `CASE static-file-no-git … observed=pass match=yes`.
2. **A body that merely contains `TEST PASSED` passes while the helper prints `TEST FAILED`.**
   `test_outputs.py:13` searches stdout for a substring that `verify.sh:62` echoes from the body, so the
   diagnostic line carries the verdict token. Receipt: `CASE token-in-body … observed=pass`, stdout
   shows `Content: TEST PASSED` then `❌ TEST FAILED: Content does not match expected output`.
3. **Status and content are two separate requests.** The first body is never compared:
   `status-then-content-split` observed pass with first body `not the content`.
4. **Only `/hello.html` on `localhost` is ever requested.** A catch-all server passes
   (`catch-all-200`), so instruction line 8 is `partly`, not `enforced`.
5. **`curl` runs without `-L` and without a timeout.** `redirect-301` fails; `slow-server-3s` passes.
6. **Only trailing newlines are forgiven.** `trailing-newlines` passes; `leading-space`,
   `trailing-space`, `crlf`, `bom`, `capitalised`, `empty-200` fail.
7. **The install comment and the install line disagree**: `verify.sh:4` says curl, `:6` installs
   `expect` (`DEBIAN_FRONTEND=noninteractive apt-get install -y expect`); `curl` is only used if
   already on `PATH`, with a `wget` fallback that carries the same two holes (`wget-token-in-body`
   observed pass).
8. **The probe matched every frozen prediction** — `cases=22 observed_pass=9 observed_fail=13
   mismatches=0`, so no V4 mismatch had to be named; the entry states that disclosure.

- The probe never runs the oracle or a real git push (no `apt-get`, `expect` or `git` in any case), and
  `test.sh` is read, not run — recorded in the entry's "What the probe does not show".

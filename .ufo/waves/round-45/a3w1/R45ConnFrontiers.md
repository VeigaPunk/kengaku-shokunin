## 2. Pattern-Joining the Round: The Landed Package and Fixture Fence

Round 45 establishes two major gate patterns that address recurring vulnerability classes identified in prior rounds:

### Class 1: Intra-Scratch Fixture Containment ("Collect First, Git Last")
- **Origin & Problem:** In round 44, `plans/round44_c1_verify.py` attempted to audit battery fixtures using `repo_breach`. However, `repo_breach` invoked `git` subprocesses (`git rev-parse --show-toplevel`, `git rev-parse --absolute-git-dir`) *before* verifying the fixture repository structure. Hostile fixtures holding `.git/commondir` (f7), `.git/config.worktree` (f8), bare un-describable repositories (f9), or regular-file config includes (f10) caused git itself to traverse outside the fixture root `d`, reading files in the parent build scratch. While the tool's intended verdict was to refuse the fixtures, it violated its own containment rule by performing out-of-fixture opens during evaluation (`contradicted=7` on the frozen refusal set).
- **Landed Fix in Round 45 C1:** `plans/fixture_fence.py` implements a strict two-phase design: **COLLECT FIRST, git LAST**. Phase 1 (`_collect`) gathers all filesystem facts (argv tokens, absence of `.git` ancestors up to build root, tree entry limits, symlinks, special files, commondir redirections, alternates, and regex scanning for config `[include]` sections) using pure Python filesystem APIs without spawning any git process. Only when the tree is proven self-contained is git allowed to execute (`_git`), with locked environment variables, empty HOME, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, and `GIT_CEILING_DIRECTORIES=d.parent`. Furthermore, `plans/round45_c1_verify.py` instruments the evaluation under `strace -f -y` inside bwrap, verifying that the entire process tree makes exactly 0 filesystem opens under build scratch outside `d`.
- **Gate Class Generalization:** Any tool or fixture validator that evaluates untrusted git fixtures must prove containment by direct filesystem inspection before invoking git, and must be verified by syscall tracing to perform zero out-of-fixture filesystem opens.

### Class 2: Predictor AST/Token Lint Bounds and Leak Suppression
- **Origin & Problem:** In round 44, criterion Q38 established that a content leg's verdict key must be generated by executing the pinned source over synthetic end states rather than stored as an answer key in the counter. However, critic `R44CritV11` discovered that Q38 had a major bypass (`v11-bypasses-4-of-7`): candidate predictors could easily bypass genuine evaluation by:
  1. Embedding a lookup table or answer dict (`{...}`) directly in the predictor code;
  2. Reading external files or executing shell commands;
  3. Iteratively hill-climbing against the counter by reading the specific mismatching state tokens printed in error logs (`at=concat#4...`).
- **Landed Fix in Round 45 C2:** The V11 check in `plans/round45_c2_verify.py` hardens the predictor verification with three complementary defenses:
  1. **Source Linting (`lint_block`):** Strict size ceiling (≤4000 B) and prohibition of memorization tokens (`{`, `}`, `import`, `open`, `os.`, `sys.`, `subprocess`, `socket`, `pathlib`, `hash`, `sha256`, `md5`, `eval(`, `exec(`, `compile(`, `states`, `.json`, `__`, `getattr`, `globals`, `locals`, `print(`).
  2. **Leak Suppression:** The counter prints only the total disagreement count (`disagree=N`), completely suppressing mismatching state labels and tokens.
  3. **Diverse State Generation:** States are dynamically constructed across 16 distinct semantic mutation kinds (`random.Random(45)`, 3 instances each = 48 states), with a non-vacuity floor requiring ≥8 passes and ≥8 fails.
- **Gate Class Generalization:** Held-out predictor blocks used to verify offline grader comprehension must be statically bounded against memorization primitives (AST/token linting) and dynamically evaluated without emitting granular failure telemetry that enables hill-climbing.

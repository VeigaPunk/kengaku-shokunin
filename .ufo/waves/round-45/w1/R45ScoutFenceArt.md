## What the prior art says the fence must do (derived, each tied to an observed row)
1. Pure-filesystem legs cannot be replaced by "run git with includes off": no such switch exists (P1, P2); `--no-pager config --file F --get-regexp '^include'` is the only measured git-based way to *list* a file's include directives with 0 outside refs, even run inside the hostile repo (E8c/E20a/E20b) — but plain Python parsing of the file is cheaper and has no Git dependency.
2. Scan **every** `.git/config*` (config, config.worktree, anything in `d/.git/`) *and* the resolved common dir's `config`/`config.worktree` (P6, P8, E18); resolve relative include paths against the including file (P5); treat `includeIf` as a breach regardless of condition (P4).
3. `commondir` (file or `GIT_COMMON_DIR`) resolving outside `d` is a breach on its own; also check `d/.git`'s gitfile target (P8, P13). Because `d/.git/config` is ignored when a commondir is present (layout(5)), the stale local config says nothing.
4. The ancestor leg must not rely on Git (ceiling blinds it, P9) and must recognise bare layouts and keep climbing past invalid `.git` entries (P10); `safe.bareRepository=explicit` is a cheap belt for the git-calling leg (P11).
5. Alternates: refuse a non-empty `objects/info/alternates` (also under the common dir) structurally (P12).
6. For the git-calling legs: env of P14 + `--no-pager`, `ceiling=d.parent` (not `d`, P9), no stdin, timeout; `rc != 0` is a breach because ceiling/safe.bareRepository failures look like "not a repo" (E4b, E19a: rc 128) — which is exactly the claim's "never clean" rule.

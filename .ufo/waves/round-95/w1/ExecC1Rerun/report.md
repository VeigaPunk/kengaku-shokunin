## Conclusions (report-only; no legs claimed)
1. **Re-measurement reproduces R95-C1 exactly**: predicate pass rc 0 at T, rc 1 at BASE and F; no defect, no mismatch; nothing that would flip the verdict.
2. **Determinism holds** across three probe runs and across Python 3.11/3.14.
3. **C11 is a whole-harness finding, not a test_outputs.py-only one.** `test_outputs.py` passes the hkey-only (C11) half fix (replay case C11, rc 0 on the vector), but the upstream repo's own suite at `0207a34f` fails that same half fix on `test_prevent_control_characters_in_headers` (value-side `assertRaises(ValueError, …)` cases), and `tests/test.sh` ANDs the original-repo half with the additional half (`ORIGINAL_EXIT_CODE -eq 0 && ADDITIONAL_EXIT_CODE -eq 0` → reward 1). The real harness therefore rejects C11; the replay's `test_outputs.py`-only scoring is the gap, and the C11 vector is a true whole-harness reject. Measured: upstream suite rc 1 on hkey-only, 1 failed / 356 passed.
4. **C15 is rejected by the whole harness only incidentally, through a collection crash.** The package shadow `bottle/__init__.py` in the probe exports only `_hkey`; every upstream test module imports `tob`/`BytesIO` from `bottle` at collection, so pytest exits rc 2 with 25 collection errors, and `test.sh` writes reward 0. The rejection is an `ImportError`, not a detection of the vulnerable `/app/bottle.py`. A complete shadow re-exporting the full bottle API would not crash collection; that variant is not measured here, so for C15 the whole-harness verdict depends on the probe's incomplete shadow. The replay's C15 vector (`test_outputs.py` alone passes, reported file stays vulnerable) is still a test_outputs.py-level finding.
5. Upstream-suite sanity: the vulnerable state fails exactly one upstream test and the solve state is fully green — the replay's positive/negative controls agree with the repo suite.

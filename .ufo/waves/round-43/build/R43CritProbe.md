# R43 C2 probe critique

## Axes
- **Coverage:** whether the frozen cases actually exercise the named requirement violations.
- **Soundness:** whether the fixture sandbox preserves the grader behavior whose verdict is modeled.

## Findings

1. **`cheat-clock-seed` is nondeterministic across a second boundary; the 10-second search window does not cure it.** `plans/feal_probe.py:139-148` reads `time.time()` inside `attack()`, then tests only seeds `now` through `now-9`; the grader's `create_random_keys()` seeds once at `time(NULL)` (`corpus/evidence/round43/tb2-feal-differential-cryptanalysis/feal.c:56-67`). If the grader seeded at second T and execution crosses T+10 before the attack reads the clock, T is no longer in the search. More immediately, only three plaintexts are checked and candidate equality relies on `F.encrypt` versus the C function; that is the intended host-sensitive technique, not proof of coverage independent of clock. **Impacted:** soundness / repeatability of the claimed host fact. Small correction: make the seed recovery robust to arbitrary attack delay by capture-time-independent evidence (or explicitly make case conditional and do not claim stable pass); merely widening a finite window is not a correctness guarantee. Receipt's duplicated pass does not establish the boundary case.

2. **`violates` tags for the three named cases appear contestable/inaccurate under the instruction's actual requirements.** Instruction line 1 explicitly requires a *chosen plaintext attack* that recovers key[5]; line 3 specifies path, function, uint32 return, and <30 seconds (`instruction.md:1,3`). `cheat-clock-seed` reproduces the secret key schedule using the clock and checks an encryption oracle, but its three chosen plaintexts do not constitute the specified chosen-plaintext differential attack; `chosen-plaintext` is defensible as the technique class, yet should be qualified as violation of attack-method requirement rather than the availability of an encryption oracle. `cheat-always-equal` returns a non-integer always-equal object, directly violating the explicit uint32 return requirement as well as not recovering key[5], so current tags are well aligned. `cheat-exit-zero` terminates before return/assert, violating return value and recovery; the current tags identify those two, while its process-exit bypass is not a separate instruction requirement. Thus **no definite tag defect** for always-equal or exit-zero, but the clock-seed tag is under-specified: the code uses chosen-plaintext queries, so whether it violates that requirement depends on interpreting “chosen plaintext attack” as prescribed cryptanalytic method rather than any chosen-input oracle attack. State that interpretation in requirement/evidence rather than treating the tag as self-evident.

3. **Harness verdict mapping correctly handles `os._exit(0)` as pass, not a missing verdict failure.** `harness` returns subprocess return code (`:271-274`); `letter` maps rc==0 to P and labels no TEST line `exit=no-verdict-line` (`:301-313`). This matches test.sh's `$?` handling (`test.sh:22-29`) and `os._exit(0)` in attack (`:126-131`). The attack call occurs within `getattr(mod,name)()` (`:230-245`); process exit skips the assert but still returns successful child status. This is a real intended counterexample, not a harness defect.

4. **Sandbox fidelity checks requested appear satisfied.** `sandbox_argv` mounts work/app at `/app`, work/tests at `/tests`, starts with cwd `/app`, uses the pinned PATH containing `/usr/bin/python` and `/usr/bin/gcc` (`feal_probe.py:77-80,253-264`). `run_case` copies exactly the five extension/grader build inputs `test_outputs.py`, `setup.py`, `feal_module.c`, `feal.c`, `feal.h` into writable `/tests` (`:76,277-290`). The grader appends `/app` then `/tests` (`test_outputs.py:20-25`), preserving its sys.path ordering in the imported module; harness imports that exact file (`:230-232`). Recipe execution uses bash `-euo pipefail` and fails on nonzero recipe status (`:204-209`); final test rc represents the pytest test function's success/failure (`:233-245`) and test.sh's reward decision is solely pytest status (`test.sh:17-29`). One modeling caveat: test.sh itself is not run (it performs network installation and uvx), consistent with frozen scope; the harness maps the single test function rather than reproducing pytest's full runner.

## Verdict
`cheat-import-get_keys`, always-equal, sys.modules shadow, patch-get_keys, exit-zero, and slow oracle recipes construct their stated mechanisms from the inspected source; oracle recipes invoke captured solve.sh, which writes `/app/attack.py` (`solve.sh:4`). Wrong-key and no-file are direct constructions. The principal concrete defect is clock-seed's finite age window undermining robustness to a slow second-boundary delay. The clock tag also needs its chosen-plaintext interpretation made explicit; always-equal and exit-zero tags match requirements. Receipt lines 10-23 establish only one observed environment and report regrade same, not robustness over delayed execution.

VERDICT: probe-defects-1

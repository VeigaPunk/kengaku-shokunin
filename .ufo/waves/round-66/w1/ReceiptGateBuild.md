## Behaviour

`--strict` (default off) keeps the default predicate and adds, per R66-C2's frozen
"Strict-mode requirements": GRADER sha vs `b165f850…` **and** the committed grader bytes;
AMALG sha vs `0a9c8e34…`; TOOLCHAIN well-formed and equal to the receipt's own
CC/GCOV/BWRAP banner tokens; the probe binding vs the committed
`plans/round65_c1_sqlite_probe.py` bytes (a `PROBE sha256=` line or the instrument header;
both validated when both present); every VECTOR line vs the frozen table; NOBIND G1–G5
present with `delta=0`. Beyond the list, one declaration tripwire: a receipt whose
probe-authored lines (all lines except `LEG`/`ENV`) carry `FABRICATED`, `nothing ran`,
`no driver run` or `no live-run data` is refused as `fabrication-declaration` (committed
receipt: 0 hits; fabricated fixture: 2 comments + 5 `RUN` driver fields). Each miss prints
`CHECK defect: <name> …` and exits 1. Strict is a superset of the default check. Default
mode's printed bytes are unchanged (`diff -u` empty on both fixtures).

## Findings (no frozen rule edited)

1. The committed R65 receipt has **no `PROBE` line** (line 2 is `# instrument
   plans/round65_c1_sqlite_probe.py version=r65-c1/1`). The frozen "PROBE sha equals the
   committed probe bytes" clause is implemented as a binding, not a sha comparison: a
   `PROBE sha256=` line when present (must equal the committed bytes; a wrong sha always
   refused), otherwise that instrument header (path must be the committed probe, version
   must equal `PROBE_VERSION`); when both are present both are validated. Strict prints the
   sha it resolved in every strict run (`CHECK strict probe sha256=f44b7283…`). Limitation:
   for the committed receipt the binding is path+version; a sha binding needs a receipt
   regenerated by a battery run, which this seat is forbidden to do.
2. The declaration tripwire refuses the sentinel's own words anywhere in the probe's voice
   and nothing else: comments in any position (q1, q8) and `RUN … driver=` fields (q7) are
   caught; `LEG`/`ENV` grader text is exempt (q5). The exemption is a trust boundary, not a
   guarantee: a declaration inside a `LEG … frag=` value is invisible (receipt `13-m` e1,
   exit 0), and scanning those values would resurrect the d2 over-refusal — the two
   measurements are the same trade-off from opposite sides. Residual survivor: semantic
   rewording (q9) or exemption placement (e1) with values copied. That is the claims' named
   limitation; the frozen strict list also does not require the `SHAPE`/`FILES`/`ENV`/
   `PREDICTION` live-evidence lines, and adding such a rule would be a new receipt-format
   rule, so this proposal does not.
3. Strict's terminal line is `PREDICATE R65-C1 strict-pass|strict-fail`, distinct from the
   default `pass|fail`, so a strict refusal is not misread as the default predicate
   failing (the default predicate passes on the fabricated fixture — that is M-1).
4. TOOLCHAIN also requires the `CC`/`GCOV`/`BWRAP` banner lines (the frozen "values the
   receipt itself carries" has no referent without them). The committed receipt has all
   three; the fabricated fixture has none.
5. Missing reference bytes (`<lane>/GRADER_REL`, `<lane>/PROBE_REL`) → `SETUP` exit 2
   (could-not-evaluate), consistent with `SETUP receipt-missing`; unreachable here (both
   hash to the frozen values, receipt `10-j`). A missing receipt *item* is always exit 1.
6. NOBIND is checked to the frozen minimum: the fabricated fixture's bare
   `NOBIND Gx delta=0` lines satisfy it and the fixture is refused by the declaration,
   toolchain and probe-binding defects instead.
7. `PROBE_VERSION` stays `r65-c1/1` and the emitter is untouched — strict adds only a
   checker mode plus selftest rows, so no emitted byte changes and the committed receipt
   stays valid.
8. Named limitation from the claims is unchanged: a declaration-free hand-copied receipt
   passes strict; the gate refuses value-free, value-mismatched and literally-declared
   fabrication only.

# R46CritC3Freeze — C3 stage-1 freeze attack

## Axes

Coverage (does the purported twelfth grader-class exemplar add a real measured capability?) and depth/calibration (does a passing predicate entail the described package and prevent verdict tuning?). The C3 claim is not yet measured; these are counterexamples against what its stage-2 protocol currently guarantees.

## Findings

1. **V13 is not an end-to-end filler discriminator.** C3 claims V13 requires a committed filler package “— a do-nothing entry and rows of the right shape —” to make V1–V12 defect (round-46-claims.md:109–111), and separately says the base, filler, and echo-receipt controls fail (114–115). V13 only requires *at least one* defect among V1–V12. Therefore an echo receipt can satisfy V13 by failing receipt/probe equality (or any other leg) even if all substantive package legs are vacuous; a filler package can fail only on missing/incorrect receipt or provenance while the semantic/content legs accept boilerplate. Conversely, making V13 reject filler does not show the passing package is non-filler: it only shows the named control is rejected. V1–V12 are individually heterogeneous and several are shape/provenance checks, not evidence that every substantive component works. The stage-1 frozen wording has no requirement that filler be rejected for a *semantic* reason, or that each substantive leg reject its corresponding omission.
   **Stage-2 sentence:** “V13 is satisfied only when the committed filler control is rejected by each named substantive semantic/content leg (not merely missing-file, digest, receipt, order, or shape legs); enumerate those legs and require their defects explicitly. Also include omission controls for receipt, mechanism, requirements, and predictor, each rejected by its corresponding leg; no single unrelated defect counts as proof.”

2. **Q30 does not bind the first actual execution.** Stage-1 says before stage 2 the probe runs only `--dry`/stage-check, and its “first recorded run follows the stage-2 commit” (claims:116–117). Inherited V8 invokes `plans/order_check.py` (round45_c2_verify.py:292–297); that gate examines committed Git history only. Its own contract says working tree/index are ignored and commit order “polices what the history proves, not what happened in a scratch clone whose output was never committed” (plans/order_check.py:12–19, 39–41). A probe can therefore be run on a scratch copy before stage 2, with no committed CASE/P10 output, then honestly appear to have its first *recorded* run after stage 2; the order checker passes without proving the first execution followed the freeze. The wording deliberately promises recorded order, not actual execution order, so this is a governance/evidence gap rather than necessarily a violation of its literal promise.
   **Stage-2 sentence:** “Q30 attests only the first committed evidence record, not the first execution; before stage 2 no graded case may be executed on any working tree, scratch clone, or host, and every probe invocation must be logged by an independent append-only runner outside the mutable claims directory; if prior execution cannot be excluded, report order unverified and C3 is not admitted.”

3. **V9 permits post-grader case-table tuning to the verdicts.** Inherited V9 constructs `want` from the receipt's `CASE ... observed=... tests=...` rows and compares the entry table to that same receipt-derived list (round45_c2_verify.py:300–320). Thus a table changed after seeing actual grader outcomes passes exactly when it copies them. V8 is an ordering gate, not a semantic independence check; V9 has no separately frozen expected case IDs/tests or independent review of table content. A receipt copied from dry output is already a named fail control, but that only detects the exact dry-echo condition, not a case table tuned after a real run. The C3 stage-1 case description defines three fixed N points and constraints, but does not state a pre-grading frozen table or a rule for distinguishing mechanistic rationale from post-hoc matching.
   **Stage-2 sentence:** “Commit a case table of IDs, inputs, expected outputs, and grader-derived pass/fail before any graded run; V9 must compare receipt rows to that independently frozen table and separately check each expected outcome against the pinned grader, never derive the table's expected values from the receipt. Record post-run rationale against pinned decisive lines; edits after first graded execution invalidate the order gate.”

4. **V11 over (listing, source) still memorizes, and can encode the full behavior table.** C3 explicitly carries forward `R45CritV11Bypass` lookup shapes as “refused” and adds lone-CR/non-newline kinds (claims:108–109), but the round-45 evidence demonstrates that the inherited lint admitted multiple behavior tables: a call-indexed 48-bit table, a feature-keyed integer/shift table, and an explicit 48-state tuple lookup; each scored `disagree=0` (R45CritV11Bypass.md:30–51, 82–92). The new predictor input is richer: its two visible inputs are directory listing and source. Listing is likely constant in the generated states (the class says the exact one-element listing must equal `['main.py.c']` before compilation); the source can itself serve as a state identifier. Unless stage 2 specifies unpredictable fresh cases or constrains the predictor to inspect a semantic property rather than table-encode `(listing, source)`, a memorizer can map the fixed sources to verdicts, use source length/features or call order, or hardcode a compact finite mapping. Merely porting “lookup shapes refused” without naming and testing representations does not prevent this; adding state kinds does not invalidate a table if the states and seed are frozen/visible before the predictor is authored. Local evidence does not show a C3-specific run, so the concrete bypass result is precedent, while this C3 application is a strong structural inference.
   **Stage-2 sentence:** “V11 must not claim non-memorization from a fixed public case set: generate hidden fresh source/listing cases after the predictor freeze with unpredictable per-run nonce content and randomized order, expose only aggregate disagreement, and test held-out source transformations; otherwise label V11 finite-sample equivalence only and require independent semantic review, not ‘lookup shapes refused’ as a guarantee.”

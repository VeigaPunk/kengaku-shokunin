## 2. Method

- One copy `S/mut/gate.py`; ten mutants generated from it by the checked generator
  `S/mut/gen.py` (each replacement asserted to occur exactly once; unified diffs kept). Every
  mutant changes one check only (m2 and m3 need two coordinated line edits to remove one logical
  condition; both edits are listed).
- Fixed detector per mutant: `python3 <mutant> --lane L --selftest --work S/mut/work/<name>`.
  `rc 0` = the gate's own vacuity guard passed = **mutant survived**; `rc 1` = refused = **killed**;
  `rc 2` = could-not-evaluate (never observed).
- Then the same bytes on the attempt-1 fixture and on the independent green skeleton (`--shonen SHONEN.md`).
- For every survivor, one purpose-built single-check probe (`S/probes/p*.md`, built from the green
  skeleton by `S/mut/build_probes.py`) run against pristine **and** against the survivor, to separate
  "the check is dead" from "the selftest has no fixture for it". The probe cross-matrix
  (`S/mut/run_probes.py`, `probe-matrix.json`) covers pristine + all 11 copies on all 7 probes.

## 4. Findings, ordered by severity

### F1 — HIGH, must-fix: the selftest's red-refusal accounting cannot detect a check that stopped failing

`selftest()` scores `if want == "fail" and got == "fail": refused += 1` in the pristine bytes; `m10`
removes the `got` clause. Alone, `m10` is invisible: its full selftest stdout is **byte-identical**
to pristine (`diff` empty) and rc 0. Composed with `m6` (a genuinely dead S3 check), the gate still
exits 0 and prints `red-refused=4`, while the same run prints `SELFTEST r3-no-discernment
want=fail got=pass`. Mechanically this defeats A2's own kill rule (b) ("a check cannot fail on its
own red fixture → the gate is vacuous, not admitted"): the guard that is supposed to prove
non-vacuity accepts a passing red fixture. The failing evidence is printed on the fixture line but
not counted; the scored artefact is the rc and the tally.

What should catch it: the tally should be derived from `want` and each fixture's `(want, got)` pair
must be asserted equal, not "every want=fail increments refused". No new fixture is needed — a
meta-assertion is; e.g. refuse any run where `want != got` regardless of counts, and compute
`expected_red = sum(want == "fail")`.

### F2 — HIGH: seven check deletions survive because the five fixtures never reach them

The union of defect codes over the committed fixtures is `{S1, S2, S3, S5}`; `S4` and `S6` never
fail in any fixture, and several sub-clauses of S1/S2 are never isolated:

| surviving mutant | clause never exercised | fixture that should exist |
|---|---|---|
| `m1-s1-order` | S1 order — `r1`'s four present headings are already in order | a skeleton with two headings swapped (`p1-order`) |
| `m2-s1-missing` | S1 missing — `r1` also fails S2/S3, masking the S1 defect | a heading removed, all other checks satisfied (`p2-missing`) |
| `m3-s1-duplicate` | S1 duplicate — no fixture repeats a heading | a duplicated `## Work performed` (`p3-duplicate`) |
| `m4-s2-count` | S2 too-many-lines — `r2` only removes a line | five box lines for four boxes (`p4-five-boxes`) |
| `m5-s2-label` | S2 label text — `r2` fails on count as well | four lines matching no box (`p5-wrong-labels`) |
| `m7-s4-pointer` | S4 pointer — `r1` passes S4 (`rows=2 pointed=2`) | two unpointed rows (`p7-unpointed-rows`) |
| `m9-s6-size` | S6 — the smallest committed fixture is 1 109 bytes and all have ≥ 6 sections | a compliant 371-byte report (`p9-minimal`) |

Under the strict reading of A2 item 3 ("Every check must fail on its own red fixture, and the gate
prints `SELFTEST n=5 red-refused=4 green-ok=1`"), the committed selftest is **false for S4 and S6**
(no red fixture at all) and unproven for S1 order/duplicate and S2 label/too-many. The two kills
that do occur (`m6`, `m8`) come from the only two fixtures that target one check each (`r3`, `r4`).
This is a coverage finding, not a predicate defect: every surviving deletion is caught by the
single-check probe, so the six checks themselves enforce the frozen sentence.

### F7 — provisional, HIGH if the working-tree draft is frozen as-is: the revision closes F2's fixtures but keeps the count-based exit

Not part of the scored A2 artifact; recorded because the working tree carried it during the wave.

The uncommitted revision (`f30ed746…`, pinned at `evidence/draft-snapshot.py`) replaces the fixture
`want` strings with exact expected defect **sets** and adds `r6-wrong-labels`, `r7-order-swapped`,
`r8-duplicate-heading`, `r9-unpointed-rows`, `r10-minimal`, `r11-five-boxes` — the seven gaps F2
names — and its own selftest passes unchanged: `SELFTEST n=11 red-refused=10 green-ok=1`, rc 0
(`evidence/concurrent-draft-f30ed746-selftest.txt`). Its final decision is still
`ok = refused == total - 1 and green_ok == 1`. A composed probe on the pinned snapshot
(accounting `if expected and ok:` → `if expected:`, plus the S3 `discernment` deletion) prints
`SELFTEST r3-no-discernment want=['S3'] got=pass MISMATCH` and still exits **0** with
`red-refused=10` (`evidence/draft-provisional-accounting.txt`). So F1's class survives the draft:
the MISMATCH is printed but does not gate the exit. If this revision is frozen, the selftest should
return 0 only when every fixture's `got == expected` (`ok = all(fixture_ok)`), with the counts kept
for reporting; it then needs its own mutation pass on its own bytes (my ten mutants were derived
from the A2 bytes and do not apply to it).

### F3 — MEDIUM: S6 is half-redundant; only the byte floor is load-bearing

`sections >= 3` is implied by S1: S1 requires six distinct `## ` headings, each appearing once, so
`sum(line.startswith("## ")) >= 6` on any S1-passing report. The live part is `size >= 400`, and the
floor is reachable: `p9-minimal` satisfies S1–S5 at **371 bytes** and fails only S6
(`S6 defect bytes=371 sections=6`). So S6 is a real check with a very thin margin, and no fixture
sits near it. (No edit proposed; reported because deleting S6 is observable only through the byte
count.)

### F4 — MEDIUM, counter-design note: S1's `missing` list is not independently load-bearing

`ok = not missing and not dup and ordered` with `ordered = positions == sorted(positions) and
len(positions) == len(HEADINGS)`: the `missing` list is a detail message, since a missing heading
already makes `len(positions) < 6`. A single-token deletion of `missing.append(...)` is therefore
behaviourally inert; `m2` deletes **both** the list and the positions-length clause to remove one
check, and only then does S1 accept `headings=5/6` (`p2-missing`: pristine `S1 defect
headings=5/6 … ordered=False`; `m2` `S1 ok headings=5/6 …`). Calibration consequence: a mutation
score that counts token-level deletions will mis-score this check, and a reviewer reading only the
`missing` path will believe the check is weaker than it is.

### F5 — LOW: S4 is stricter than the frozen sentence for non-`claim` table headers

The frozen S4 says "at least two table rows and every **claim** row carries a backticked token or a
7+-hex commit hash". The gate treats every row whose first cell does not start with `claim` /
`claim / axis` as a claim row, including a table **header**. Evidence: the green skeleton with only
its header changed to `| item | before | after | command | verdict |` gives
`S4 defect rows=3 pointed=2`, `DEFECTS n=1`, rc 1 (`probes/p8-header-word.md`), although both data
rows are pointed. A report whose measurement table is headed `| item |` is therefore falsely
refused. Not edited; reported as over-strictness relative to the frozen wording (the gate's own
skeleton uses `| claim |`, so the landed report shape passes).

### F6 — INFO, calibration: the attempt-1 fixture is over-determined and cannot isolate a check

It fails S1+S2+S3 simultaneously (`DEFECTS n=3`), so all ten mutants still fail it; `m2` merely
narrows it to `DEFECTS n=2` (`S1 ok …`). Kill rule (a) holds under every mutant, but the fixture
cannot show *which* check caught it: a dead check is masked by the remaining two, so it is weak as
the sole red regression. The per-check probes are the detector that has resolution.

## 7. Bottom line for the L1

The gate's six checks all enforce the frozen sentence as written — each of the seven surviving
check-deletions is behaviourally observable and is refused by a purpose-built single-check fixture,
and no mutant flips the attempt-1 red or the green pass. What does **not** hold is A2 item 3's own
selftest claim: it has no fixture for S4 or S6, no isolating fixture for S1 order/duplicate or S2
label/extra-line, and its refusal accounting accepts a red fixture that passed (F1), which is the
one gap that can hide a dead check without leaving a trace. The two must-fix items are F1
(accounting) and F2 (fixtures for S1-order, S1-missing, S1-duplicate, S2-count/label, S4, S6); the
committed gate was not edited by this seat. A working-tree revision appeared during the wave (F7):
it supplies the F2 fixtures and exact defect sets, but its exit is still count-based, so if it is
frozen it needs an `all(fixture_ok)` gate and its own mutation pass on its own bytes; until then the
A2 bytes at `18fbfc21…` remain the artifact of record.

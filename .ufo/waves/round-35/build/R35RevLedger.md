## 2. Is the mismatch logic a calibration count per addendum §9?

**Yes, faithful, with one nuance.** Addendum §9 (Claim sizing), `scripts/hyaku/lane-addendum.md:282-283`: "A calibration claim must count mismatches between the lane's self-assessment (SCORECARD/SHONEN) and observed repo state. It cannot be an assertion." The ledger operationalizes exactly that: self-assessment = the row's `status` field, observed state = the check's observation, mismatch counted in **both** directions — `closed` whose check fails and `open` whose check passes (`agree = (is_closed and ok) or (st == "open" and not ok)`, `defect_ledger.py:132`; `mism += not agree`). It cannot be reached by assertion: flip-only control reproduces (`control-c2-flip.txt`: `closed=5 observed_pass=1 mismatches=4`; my fixture T7 identical), status typo fails closed (T9: `Closed` → `closed=0 mismatches=5`), empty ledger fails (`T12: rows=0 … PREDICATE C2 fail`), corrupt/missing ledger crashes to exit 1 (T10/T11), and a per-check crash is an observed failure, never a pass (`defect_ledger.py:126-127`).

Nuance: §9 names the self-assessment locus as SCORECARD/SHONEN; the ledger's is its own `status` field — a new self-assessment surface the lane created and then measures itself against. That is the intended game (the frozen predicate forces all five rows closed and passing), and D4's SCORECARD-correction requirement ties the SCORECARD surface back in. Defensible; noted for the record.

## 3. Is the row schema sufficient for considerthese proposal 2?

**Sufficient for this round's claim; partial vs the proposal** (`considerthese/2026-10-25.md:39-45`).

- Implemented fields: `id, class, opened_round, source, check, status, closed_round, recurrence_of` (`corpus/defects.jsonl`, 5 rows; `source` line refs verified against the actual spotcheck lines 75–79).
- Proposal (a) "re-runs every closed defect's check at tip forever" — **implemented and strengthened**: every row (open too) re-runs on every invocation, which is what makes the `open+pass` mismatch direction possible.
- Proposal (b) "blocks pre-registration when a class recurs twice" — **not implemented**: `recurrence_of` is recorded, never read (`grep -n recurrence_of plans/defect_ledger.py` → 0 hits).
- Proposal (c) tip-receipt validator over `corpus/evidence/**` — **not implemented**; narrowest analogue is `r34_d3`'s single-manifest digest check.
- Schema deviations: proposal's `closing_commit` → `closed_round` (round number, no commit pin — weaker provenance for "at what tip did this close"); `recurrence` → `recurrence_of` (a link, no count — cannot express (b)'s twice-rule). Missing a free-text `scope`/`note` field (would have carried F3's undocumented extra roots); `source` line numbers are never validated by the checker.

The claims only mine the ledger idea ("one persistent ledger instead of a new `plans/roundNN_defects.py` per round"), so implementing (a) alone is honest — but the schema as-is cannot express (b) or (c) without another migration.

**F2 [low-medium] — D1 measures the routed inventory but not the routed fix.** Routed D1 ends "leave `status --porcelain` empty"; the check counts only untracked paths inside its pathspec (`defect_ledger.py:40-42`). **F4 [low] — a broken check binding reads "agree" while the row is open.** `fn is None → ok=False`; with `status=open`, `agree = (open and not ok) = True` → fixture T8 prints `R34-D1 status=open observed=fail agree=yes unknown check 'nope'`. With `status=closed` it counts correctly (closed+fail → mismatch). Recommendation: treat a missing check as a mismatch regardless of status, or print `agree=NO check-missing`.

**F5 [low] — D3 digests are not pinned to the upstream-verified values.** The spot-check verified `test_outputs.py`/`test.sh` hashes against upstream at the pinned commit (`44a05a24…`, `9ede4664…`, spotcheck §2 evaluator-capture row); `r34_d3` only requires the two names listed and digests == local file bytes (`defect_ledger.py:62-65`). **F6 [info] — schema gaps vs proposal 2** (detailed in §3): no `closing_commit`, no recurrence count for the (b) rule, no scope/note field, `source`/`closed_round`/`recurrence_of` never read by `main()` (only `check`, `status`, `id` are consumed).

**F7 [info] — the frozen `rows=5` is enforced only by the receipt comparison, not by code.** `good = bool(rows) and closed == len(rows) and passed == len(rows) and mism == 0` (`defect_ledger.py:138`) is row-count-agnostic: a sixth row, all closed+pass, would print `rows=6 … PREDICATE C2 pass` exit 0.

# R35CritScope — scope review

## Axes
- **Adjacency:** whether this stays static evaluation interpretation rather than assuming ownership of benchmark/task runtime validity or biology.
- **Coverage:** whether the changed surface is the named frontier-to-core scoring-code surface, rather than an implied broader benchmark surface.

## Counterexample / evidence
C1 is inside the round-28/29a2 boundary **if precisely scoped**: it inspects a pinned maintainer grader and executes that grader locally against synthetic inputs, much like round 29's source-faithful generator projection. Both derive bounded behavior from pinned source; neither runs the benchmark environment or validates live/deployed task artifacts. Executing the grader does cross from reading-only into execution of upstream code, but execution alone is not the prohibited benchmark run: here the tested objects are constructed synthetic gBlocks, and the instrument observes this test function's behavior, not a submitted task solution or hosted reward.

Evidence: the entry says the probe makes 18 synthetic inputs and runs the captured `test_outputs.py` under Biopython 1.85, explicitly not in the task image (`corpus/knowledge/tb2-protein-assembly-grader.md:15-19,87-88`). Its results are 5 pass / 13 fail / 0 mismatches (`corpus/evidence/round35/tb2-grader-probe.txt:21`). The entry expressly disclaims task validity, biological correctness, Harbor runtime, and model performance (`...grader.md:82-88`). PROVINCE round 29 already admits a pinned generator projection while keeping deployment configs and runtime task validity open (`PROVINCE.md:204-211`); round29a2 says published maintainer instruments are read, not run, and explicitly refuses benchmark execution/certification (`PROVINCE.md:213-223`).

Strongest counterexample: because the probe imports/executes the actual grader, a reader may treat passing synthetic artifacts as evidence a real task answer is valid, or take grader agreement as biological truth. That inference is invalid: synthetic fixture inputs are not task-derived answer artifacts, and the entry itself notes literals are not checked against PDB/FPbase/antibody sources (`...grader.md:11-14,28-31,82-88`). The instrument exposes grader predicates and blind spots (e.g. G-only linker passes, lines 60,70-71), not whether those predicates or literal sequences are biologically correct. Nor are there model outputs or trials, so no performance claim follows.

## Smallest safe wording correction
Entry's current negative-space text is strong; keep it. Make the boundary explicit in its title/lead and in PROVINCE: call this **offline execution of the pinned grader function on lane-authored synthetic gBlocks**, not “running the benchmark,” “task validity,” or validating solutions. State the observable is only the grader's local pass/fail/assertion behavior at the pinned revision; it does not establish that any real task artifact passes, that grader checks match task instructions/source truth, biological correctness/expression, Harbor/runtime reward, or any model performance. Label the 18 fixtures synthetic and constructed from grader literals; distinguish predictions matching observations from external correctness.

Suggested PROVINCE addition: “Core addition: static interpretation and offline synthetic-fixture execution of one pinned Terminal-Bench 2.0 `protein-assembly` grader function. This records how that captured function responds to lane-authored inputs only; it does not run Terminal-Bench, validate/certify the task or a real submission, establish biological correctness, measure model performance, or establish runtime/hosted-judge behavior. Task validity and runtime remain open.” This narrows round29a2's general ‘does not run a benchmark’ statement without implying a real benchmark run. Do not say this closes runtime task validity.

## Axis naming
“Coverage” is defensible **only as source/surface coverage**: frozen C1 explicitly advances one named frontier clause (“other benchmarks' scoring code”) to core for one task (`plans/round-35-claims.md:13-18`), and the new entry/counter make that specific grader surface inspectable. It is not coverage of task validity, biological space, task solutions, or TB2/model performance. The §9 rule requires naming the surface changed and a command showing it unmoved (`scripts/hyaku/lane-addendum.md:295-299`). Phrase the axis as **coverage (one pinned task's grader/scoring-code surface)**; if claiming broader benchmark coverage, the claim is false. The score remains governed by its frozen predicate and existing cap; this critique does not authorize a score move.

## Counterexample / evidence

The strongest concrete counterexample is a pinned transcript-emitter probe: a probe implementation can print a pre-authored receipt verbatim for its grade path and emit a crafted `--dry` table / `--stage-check` success, without invoking the captured grader, gcc, or the seed/recipe. If stage-2 pins that implementation and stage-3 commits its matching text, checks that establish only byte identity and textual consistency cannot distinguish it from a grading probe.

Evidence at the frozen base:

- `plans/pkg_gate.py:267-285`: P10 runs `spec["probe_cmd"]`, then accepts iff return code is 0 and stdout is byte-equal to the receipt. It does not independently execute the captured grader. `cmd_package` includes P10 only when `--rerun` is supplied (`:305-309`). The current round-46 spec (`plans/pkg-spec-r46.json:7-11`) selects the probe command; pins in `frozen_instruments` bind bytes, not behavior (`:53-56`).
- `plans/round46_c3_verify.py:347-357`: V5 checks probe and dry-table digests and runs `--dry`, comparing stdout with the dry table. It does not grade cases. V4/V7/V9 read receipt text (`:313-344`, `:374-413`, `:423-453`); V8 checks history. Thus on the present base the only full-grade binding is P10's trust in the pinned probe's implementation.
- The C2 freeze expressly says pre-receipt controls disable P10 (claims §C2(b), lines 117-122), then requires stage-2 probe `--stage-check` and seed+recipe grade path (lines 129-131). The latter is a necessary countermeasure to the transcript-emitter, but the claims do not specify an independent verifier that the probe's grade path actually invokes captured seed+recipe/grader; checking that the candidate's code contains/runs those steps needs to be part of falsifiable counter evidence, not merely a self-reported stage-check receipt.
- Round-49 V8 as frozen only establishes commit ordering / presence of `CASE … observed=` lines; `plans/order_check.py` scans committed blobs under `.ufo/waves/round-NN/claims/` only (`:163-164`, `:192-198`). This cannot establish that output was generated by executing a grader. A scratch run or precomputed transcript is not provable from commit history; V8's own docstring names the general limit that commit order does not establish scratch history (`:39-40`).
- Frozen receipt was preserved and checked against its spec pin: `sha256sum corpus/evidence/round46/polyglot-c-py-probe.txt` and `json.load(...)["receipt_sha256"]` both returned `dd0e35464bc1b19c692d45a419a33c7bcf2d8fd2753783dd13a54f059531c277`. No receipt bytes were changed.

The counterexample is conditional on stage-2 pins accepting a transcript-emitter; it is **not** a demonstrated R49-C2 pass, because the R49 counter does not yet exist at the mandated frozen base. It is also not a claim that the honest probe is defective: the observed assurance gap is that byte equality / digest pins alone do not prove the pinned program performed grading. The frozen `--stage-check` requirement provides a useful falsifiable control, but a passing self-authored transcript is not sufficient to establish it.

## Smallest safe correction

Require one independent, counter-owned execution check on the pinned captured grader and recipe/seed, using the amended frozen cases, and compare the independently produced per-case verdicts to the stage-3 receipt. Ensure the check does not import/execute the candidate probe as its oracle. Separately keep the required `--stage-check` and verify its expected per-case outcomes, not just the probe's own success summary. Then the stage-3 order rule remains useful for sequencing but is not treated as proof of execution provenance.

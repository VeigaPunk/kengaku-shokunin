# code-from-image: exact-file grader replay, not image understanding

The pinned grader has two test functions, in definition order:

| Leg | Actual graded surface | Acceptance rule | Source |
|---|---|---|---|
| exists | `/app/output.txt` | Path exists | captured grader :10-15 |
| correct | text read from the same file | `.strip()` starts with the six-character hint and equals the full fixed answer | captured grader :18-31 |

The task statement asks an agent to implement pseudocode shown in `/app/code.png`. The grader does not inspect the image, the implementation, or how the answer was obtained. A replay that stages the expected text prices only the grader's acceptance surface. It is **not** evidence of an agent solving the task, image understanding, model accuracy, or contamination resistance.

## Frozen end-state witnesses

`plans/round83-cases.json` is the end-state table; `plans/round-83-claims.md` froze it before scoring. The two function calls run independently. An assertion failure or missing-file exception is a failed leg; another exception is an unevaluated setup defect, not a convenient red witness.

- An absent file fails both legs.
- An empty existing file passes existence but fails the prefix assertion.
- The exact answer, including a whitespace-padded form, passes both legs because the grader strips whitespace.
- The prefix alone and the answer with an extra suffix pass the prefix assertion but fail equality.
- A changed prefix and an uppercased answer fail the prefix assertion.

These are **predictions from the captured code**, not a new benchmark score. The receipt's observed CASE vectors and the re-executing counter are the separate empirical evidence.

## Reproduction boundary

The replay executes the captured module itself inside bubblewrap. `/usr` and `/etc` are read-only; the case directory is bound as `/app`; the grader is read-only at `/tests`. No host `/app` is written, and Path/open are not patched. The host Python and OpenSSL versions, subject/table/tool hashes, measured git revision and exact command are receipt fields. The counter reconstructs argv rather than executing a receipt's arbitrary shell text.

The scope is one member of the existing file-artifact class. The round-82 sweep is a historical census of 26 executed members at its own revision; it is not silently widened to include this member. No new grader class or evaluation method is claimed.

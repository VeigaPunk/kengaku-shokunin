## Rules as implemented

Measured subject: one entry `corpus/knowledge/tb2-code-from-image-offline.md`; the
successor admission is the `## Gate` of `corpus/lessons/round-84.md`. With `--rev`
both are read by `git show REV:path`; without it the working tree bytes are read and
Q13 still needs a commit (HEAD). Only an entry absent at the revision, an unreadable
revision, a lane that is not a git repository, or an unclonable gate repository gives
exit 2 (`COULD-NOT-EVALUATE`). `defects = q1 + q21 + q13` over `entries=1`.

Q1 — header contract. Lines 1..3 must start at column 0 with `source:`,
`verified-at:`, `recheck:`. The recheck body must contain both
(a) a marker: an ISO date matching `(?<![0-9])(\d{4})-(\d{2})-(\d{2})(?![0-9])` that
is a real calendar date, or a cadence matching
`(?<![\w-])(?:daily|weekly|bi-?weekly|fortnightly|monthly|quarterly|semi-?annual(ly)?|annual(ly)?|yearly|per[- ]release|every\s+\d+\s*(?:days?|d|weeks?|w|months?|mo|hours?|h))(?![\w-])` (case-insensitive);
and (b) a named action: a command matching
`(?<![\w./-])(?:python3?|bash|sh|zsh|npx|uv|make|git|jq|rg|go|cargo|npm|node|perl|ruby|curl|wget|bwrap|bubblewrap)(?![\w-])` or `(?:plans|scripts)/…\.(py|sh)`,
or `(?<![\w-])(?:re-?verify|re-?run)(?![\w-])` followed by a concrete action token
(a backticked span, a token containing `/`, a file with a `.py|.sh|.json|.md|.txt|.yaml`
extension, or a command name). Missing marker → `recheck-no-date-or-cadence`; missing
action → `recheck-no-action`; wrong header line → `lineN-not-<prefix>`.

Q21 — pin continuity. Pins are `(?<![0-9a-f])[0-9a-f]{40}(?![0-9a-f])` on line 1
(boundaries stop a 64-hex digest from donating a 40-hex prefix). Every pin must appear
literally on the recheck line, or the recheck line must contain `(?<![\w-])(?:re-?pin(ned|ning)?|pin(ned|ning)?)(?![\w-])` together with a cadence token (an ISO date
is not a cadence here). No pin on the source line → q21=0 with detail `pin-absent`.

Q13 — successor admission. `plans/gate_timing_check.py --lesson
corpus/lessons/round-84.md --commit REV`, using the checker bytes at REV, run against
a `git clone --shared --no-checkout` of the measured revision (never the lane worktree).
Exit 0 → q13=0; any other exit, or an absent lesson → q13=1. The checker's own
requirement of a line-start `writer:` field on the candidate is folded into q13 (a
missing writer makes the checker exit 1); it is not a fourth defect class.

INFO — `INFO writer=present|absent` reports whether the entry has a line matching
`^writer:\s*\S` (multiline). Informational only; it never changes a count.

In worktree mode a Gate that is not byte-identical to HEAD's is treated as
`lesson-absent` (an uncommitted admission is not an admitting tree); this is deliberate.

## Determinism

Verdicts are deterministic functions of the measured bytes and the checker at the
measured revision. Q13 details keep only the checker's `reasons:` line (or the first
diagnostic line) with whitespace collapsed and commit hashes never echoed. Fixture
commit SHAs vary with the clock but are never printed. `git show` text decoding
replaces invalid UTF-8; the measured files are UTF-8, and a replacement byte could
only weaken, not fabricate, a header match. The two boundary choices that are mine,
not the frozen text's, are documented above: the Q1 action must be concrete (a bare
prose `re-verify` without a command/path/backtick is not an action), and the Q21
escape reads "pin/re-pin with a cadence" as a cadence token, not an ISO date. No rule
failed to be made deterministic; the only external dependency is the checker script
itself, which is pinned to the measured revision by construction.

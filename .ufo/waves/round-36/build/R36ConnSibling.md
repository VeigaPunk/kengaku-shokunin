## 4. Contradictions stated explicitly (not smoothed)

- **No sibling claims kengaku's ground — but the closest sibling method lives in a different lane and is not cited by kengaku's frozen instruments.** The C1 battery at `plans/round36_c1_verify.py` builds its own accept/reject fixtures from committed round-35 bytes and defines its own `false_green`/`false_red`/`unevaluated` classes. mado's parallel manifest is *compatible* (same accept/reject discipline, different objects) but *not* interchangeable: mado's controls are per-lane committed trees with `expect` verdicts, kengaku's are per-fixture gate exit codes (0 accept / 1 reject / other unevaluated). A reader who assumed they were the same instrument would mis-score both. This contradiction is recorded, not resolved.
- **The `## Located quotes` name is shared across lanes with different shapes.** tameshi and kumitate use the heading for prose bullet lists (occurrence counts / source-id bullets); kengaku's C1 gate parses a `| quote | file:line |` table and treats an unparsed row as a defect. The shared name is a coincidence of vocabulary, not shared ownership, and the gate must not key on the heading string — it must parse the table. This is the concrete overfitting risk the dispatch warned about, and it exists on the *section-name* axis as well as the fixture-name axis.
- **`kumitate cap-run` is not prior art for C1.** It is a sandboxed child-process runner (`contract kumitate-cap-run-v2`), not a junk battery or mutation gate; `gate-mutants.mjs` is. Any report that cites "cap-run" as the sibling mutation gate would be wrong.

## 5. Risks

1. **Overfitting on the heading string.** If the wave-2 mutant swaps `## Located quotes` for a near-miss heading, a gate that keys on the literal heading string rather than on the table grammar will mis-score. The sibling evidence above (kotoba `:36` "an empty quote cell is FALSE CONTENT … must be rejected, never 'found'") is the model for shape-based, not name-based, recognition.
2. **Duplicating the fleet registry contract.** The C1 gate's SOURCES checks (11 cells, tier A, status mined, used-by = the entry, teaches ≥8 words, pairwise distinct) partly overlap `scripts/sources-census.sh` E/W semantics and `kumitate/scripts/sources-check.mjs`. If the gate's row parser disagrees with the census on any cell, the two authorities will contradict each other in the same round report. Prefer: the gate validates *package-specific* rules (rows present once, `used-by` exactly the entry, teaches distinctness) and leaves generic row shape to the census.
3. **The manifest-drift trap.** mado's driver re-reads the frozen manifest and dies on `manifest-id-drift` / `manifest-control-set-drift` / `manifest-expectation-drift` (`check-counter-discrimination.py:107-116`). kengaku's C1 counter builds its battery at run time from committed bytes; a wave-2 mutant that adds a fixture without a matching expectation would be *unevaluated* rather than *wrong*. That is the intended semantic, but it must be stated so a reader does not mistake `unevaluated=1` for `false_green=1`.
4. **Two adjacent lanes both claim "the" quote-verification instrument for their own lane** (chousa's live re-open, kotoba's pinned-commit re-read, kasegi's anchor check, kotodama's cap). If kengaku's C1 gate's located-quote rule is quoted without its scope ("pinned local capture file, not a live URL"), the round report will read as a fleet-wide standard when it is lane-local.
